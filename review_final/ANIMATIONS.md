# CardFlow — анимации и микроинтеракции

Источник: инвентаризация по коду (`review_final/tools/anim_inventory.py` → `raw/animations.txt`, 65 вхождений в `lib/ui/`) + токены `lib/ui/theme/app_tokens.dart` (`AppDurations`) и `lib/ui/motion.dart` (`AppMotion`).
Живые кадры анимаций не записаны (видео не снималось) — оценки по коду и ключевым кадрам до/после (`pump()`-сценарии рендеров).

---

## 1. Система токенов

| Токен | Значение | Назначение по комментарию в коде |
|---|---|---|
| `AppDurations.quick` | **120 мс** | Отклик на нажатие/ховер, смена цвета |
| `AppDurations.base` | **180 мс** | Смена состояния: цвет, фокус, раскрытие подсказки |
| `AppDurations.medium` | **220 мс** | Переход между карточками, появление панели, смена шага |
| `AppDurations.slow` | **280 мс** | Переход состояний экрана, появление диалога |
| `AppDurations.flip` | **300 мс** | Переворот карточки |
| `AppDurations.enter` | **240 мс** | Появление списка/панели экрана |

Кривые `AppMotion`: `enter = easeOutCubic`, `standard = easeInOutCubic`, `feedback = easeOut`, `expressive = easeInOutCubicEmphasized`.
Пружины: expressive 380 / 0,8; standard 700 / 0,9; effects 1600 / 1,0.
`AppMotion.reduce(context)` — единая проверка `MediaQuery.disableAnimations`; `AppMotion.duration(context, d)` возвращает `Duration.zero` при reduced motion.

Требование гейта V9: 120–160 / 200–250 / 280–350 мс и единые кривые.
Факт: **180 и 240 мс не попадают ни в одну корзину**; 120, 220, 280, 300 — попадают.

## 3. Что работает хорошо

1. **Переворот карточки 300 мс** с `easeInOutCubic` и 3D-перспективой; смена лица ровно на 50 % — плавно, без «мигания» (по коду и кадрам до/после).
2. **Появление панели оценок** — fade + сдвиг 12 px за 220 мс: аккуратный отклик, панель не «прыгает».
3. **Единые кривые** (`easeOutCubic` для появления, `easeInOutCubic` для переходов) — нет случайных `Curves.linear/elastic`.
4. **Reduced motion** реализован централизованно (`AppMotion.reduce`/`duration`) и покрывает главные переходы: переворот, панель, страницы, изображение, пульс, «тряску».
5. **Фокус**: видимая рамка/кольцо 2 px (`onSurface`/`primary`) — не только заливка 14 % (доступность).
6. **Hover** у кнопок/панелей/строк — 6 % primary, из темы.

## 4. Разрывы (что не соответствует гейту V9)

| # | Проблема | Факт | Требование |
|---|---|---|---|
| A1 | **Нет отклика на карточку-объект** | Вся карточка кликабельна (`GestureDetector`), но курсор остаётся стрелкой, hover/focus нет; на десктопе «клик по карточке раскрывает ответ» невидим | `MouseRegion(cursor: click)`, hover-подсветка (граница/фон 2–4 %), focus-ring при Tab |
| A2 | **Reduced motion неполный** | Не учитывают: авто-прокрутка ленты 300 мс, пружина свайпа, `AnimatedContainer` чипов (120 мс) и сайдбара (180 мс), `SpringSimulation` в «Тесте» | Все переходы — через `AppMotion.duration/curve`; при reduce — мгновенно |
| A3 | **Шкала не в трёх корзинах** | 180 и 240 мс — вне 120–160/200–250/280–350; 120 мс в чипе — литерал, не токен | Привести к 120/140/160, 200/220/250, 280/300/350; литералы запрещены |
| A4 | **Разнобой пружин** | Лента: expressive 380/0,8 по умолчанию, standard 700/0,9 при `motion=standard`; «Тест» — standard; «Пары» — стандартная + «тряска»; карточка — кривые, не пружины | Одна пружина на класс взаимодействий: expressive — hero, standard — служебные, effects — цвет |
| A5 | **Нет анимации появления экранов-состояний** | «Сессия завершена», «пусто», «ошибка» появляются подменой содержимого без перехода (AppEmptyState — статичный) | Появление состояния: fade/scale 180–220 мс (или общий `AnimatedSwitcher` на body) |
| A6 | **Нет скелетона загрузки** | Загрузка — спиннер; контент появляется скачком (V8) | Skeleton с теми же размерами, что и контент; переход 180 мс |
| A7 | **Прогресс ленты: 1400 мс пульс** | Повторяющаяся анимация не имеет паузы при `disableAnimations`? — есть проверка reduce, но пульс — единственная «живая» анимация, отвлекает на 2K/4K | Пульс — только при `motion=expressive`; амплитуда минимальна |
| A8 | **Длительность диалога не задана темой** | `showDialog` использует M3-дефолт (150–200 мс), а полноэкранный просмотр — 180 мс; в токенах есть `slow=280` | Единая длительность диалога 200–220 мс (из токенов), листы — 280 |

## 5. Требования к исправлению (без патчей)

1. **Курсор и hover карточки**: кликабельная поверхность обязана показывать `SystemMouseCursors.click` и hover-состояние; focus-ring — при навигации Tab.
2. **Reduced motion — 100 %**: любая анимация/пружина/авто-прокрутка проверяет `AppMotion.reduce`; при reduce — `Duration.zero` (пружина — `jumpTo(цель)`).
3. **Три корзины длительностей**: 120–160 (отклик), 200–250 (смена состояния), 280–350 (переходы/диалоги). Токены `base=180`, `enter=240` привести к корзинам; литералы `120`/`180` заменить токенами.
4. **Одна пружина на класс**: expressive (380/0,8) — только hero-моменты (переворот, завершение), standard (700/0,9) — служебные переходы; смешивание в «Тесте»/«Парах» убрать.
5. **Анимация состояний**: «завершено/пусто/ошибка» появляются fade/scale 180–220 мс; «Готово» — hero-число с count-up 280–350 мс (по желанию, но единообразно).
6. **Скелетоны**: геометрия контента до загрузки (карточка, список колод, статистика), переход 180 мс.
7. **Документировать инвентарь**: таблица «элемент → длительность → кривая → reduce» в `docs/` как часть дизайн-системы (сейчас инвентарь существует только в этом аудите).
