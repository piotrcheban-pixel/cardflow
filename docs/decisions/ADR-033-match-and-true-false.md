# ADR-033 — Режимы «Подбор пар» и «Верно/Неверно»

**Дата:** 2026-11-16 · **Итерация:** 7.16 · **Статус:** принято

## Контекст

Владелец: больше разнообразия распознавания — Quizlet Match и True/False,
Anki-подобные свайпы. Требования:

- «Подбор пар»: 6 пар, таймер, локальный лучший результат, **без FSRS**;
- «Верно/Неверно»: утверждение из правильного/неправильного ответа 50/50, кнопки
  и свайпы, FSRS **только для due-карточек**;
- те же ограничения: ru-локаль, схема БД v1, покрытие ≥ 80 %, никаких мёртвых
  кнопок, ARB.

## Решение

### «Подбор пар»

- Домен `lib/domain/study/match_game.dart`: `MatchGame.build` берёт до 6
  карточек с непустыми front/back (cloze исключён), перемешивает детерминированно
  по seed, отдаёт 12 `MatchTile`. Состояние: `selected`, `matched`,
  `mismatch`, `moves`, `select(index) → selected|matched|mismatch|ignored`,
  `clearMismatch()`. Совпадение — один `cardId` и разные стороны.
- UI `lib/ui/study/match_screen.dart`: сетка 3/4 колонки, таймер с первого тапа
  (`Stopwatch` + `Timer.periodic(100 мс)`), встряхивание несовпавшей пары
  (spring-подобная синусоида), исчезновение найденной пары, итог с временем и
  лучшим результатом, «Ещё раз»/«Готово». Haptics по настройке.
- Лучший результат — `MatchBestStore` (`lib/domain/study/match_best_store.dart`),
  drift-реализация `DriftMatchBestStore` пишет JSON v1 в существующую
  `app_settings` (ключ `study.match.best`, `{"version":1,"decks":{...}}`);
  **схема БД не меняется**, битый JSON/неизвестная версия читаются как пустые.
- FSRS не пишется: `StudyMode.match` (`canWriteFsrs = false`), UI не создаёт
  `StudySessionController`.

### «Верно/Неверно»

- Домен `lib/domain/study/true_false_question.dart`: для карточки выбирается
  альтернативный ответ из колоды (typable, не совпадающий после нормализации);
  `Random(seed ^ card.id).nextBool()` решает, показать правильный ответ или
  дистрактор (50/50, воспроизводимо). Нет альтернативы — вопрос не строится.
- UI `lib/ui/study/true_false_screen.dart`: front, утверждение «Ответ: …»,
  кнопки ✓/✗, свайп вправо/влево (порог 40 px или скорость 250 px/с), плашка
  результата, «Далее» (авто-переход 0,9 с у верного, кроме reduce motion), итоги
  и повтор ошибок через общий `StudySessionController`.
- Оценка: верно → `Good`, неверно → `Again`; `StudyMode.trueFalse` пишет FSRS
  только для due/новых карточек, остальные — `PracticeRepository` с
  `mode='true_false'` (ADR-032).

## Последствия

- + Игровой и swipe-режимы переиспользуют контроллер/итоги/политику FSRS 7.15.
- + Лучший результат хранится без миграции БД и виден после перезапуска.
- − Таймер «Пары» — `Timer.periodic` экрана (не тикает в фоне; при уходе с
  экрана останавливается/уничтожается). Тесты используют `pump(Duration)`, не
  `pumpAndSettle`.
- − Статистика/экспорт не включают лучшие результаты «Пар» (локальный кэш);
  «Верно/Неверно» пишет журнал `review_logs` наравне с 7.15, лимиты не
  учитываются (L88).
