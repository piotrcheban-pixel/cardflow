# ADR-007 — M3E-интеграция корня и семантика списка колод (итерация 1)

**Дата:** 2026-11-12 · **Статус:** принято (итерация 1) · **Связано:** SPEC A4.3–A4.5, A6.2, A6.3, A6.9; ADR-001, ADR-002, ADR-005, ADR-006; `journal/iteration-1/plan.md` (задачи 1.6–1.8); `journal/iteration-1/red-ui.md`, `red-data.md`

## Контекст

1. ADR-001 отложил runtime-спайк S2 (`M3EMaterialApp` + `M3EThemeData` + ru + компоненты) до первого реального экрана — итерация 1, экран «Колоды». Требовалось проверить M3E-виджеты в реальном дереве и в widget-тестах, не смешивая библиотеки вне слоя `lib/ui/m3e/`.
2. Корневая навигация проекта — `GoRouter` (AGENTS.md). У `M3EMaterialApp` 1.2.0 **нет** параметра `routerConfig` (и вообще `MaterialApp.router`-режима) — он принимает только `home/routes/onGenerateRoute`, что несовместимо с `GoRouter`.
3. SPEC A6.2 задаёт элементы экрана «Колоды», но не задаёт точную семантику поиска, фильтров, порядка и архива (что считать «Новые»/«В процессе»/«Просроченные» для колоды, куда деваются архивные колоды). Это нужно зафиксировать один раз, иначе UI и репозиторий разойдутся.

## Решение

### 1. M3E-интеграция: `MaterialApp.router` + `M3ETheme` в `builder`

Корень (`lib/ui/app.dart`): `MaterialApp.router` (`material_ui`) + M3E-тема в `builder`:

```dart
builder: (context, child) {
  final brightness = Theme.of(context).brightness;
  final data = brightness == Brightness.dark
      ? M3EThemeData.dark(seedColor: AppTheme.seedColor)
      : M3EThemeData.light(seedColor: AppTheme.seedColor);
  return M3ETheme(data: data, child: child ?? const SizedBox.shrink());
}
```

`M3EMaterialApp` **не используется** в MVP: он не принимает `routerConfig` (проверено по исходникам пакета 1.2.0: `m3e_material_app.dart` содержит только `home/routes/onGenerateRoute`). Для dynamic color (A4.1) M3E-тема строится из бренд-сида; dynamic color подключается в итерации 7 (KNOWN_LIMITATIONS L6c) — тогда рассмотреть `M3EMaterialApp`/`M3EThemeController` либо обновление библиотеки.

**Runtime-спайк S2 — успешен** (подтверждено widget-тестами `test/widget/m3e/m3e_spike_test.dart` и экранными тестами): под `M3ETheme` реально работают:

| M3E-компонент | Где используется |
|---|---|
| `M3ECard` | карточка колоды в списке «Колоды» |
| `M3EChip` (filter) | чипы фильтра (Все / Новые / В процессе / Просроченные) |
| `M3ESnackbar.show` | undo-снекбар архива, успех импорта/экспорта |
| `M3EExtendedFab` | FAB «Создать колоду» |
| `M3ESplitButton<String>` | Split-кнопка «Создать» (Вручную / Импорт .zip) |

M3E-импорты — только через `lib/ui/m3e/m3e.dart` (guard `architecture_test`); base Material — `material_ui` (ADR-001). Fallback на вариант 2 ADR-001 (собственные обёртки поверх `material_ui`) не потребовался.

### 2. Семантика списка колод (единая для репозитория и UI)

- **Порядок:** `updated_at` DESC; при равенстве — `name` ASC (стабильный порядок в тестах и UI).
- **Поиск:** подстрока по **имени колоды**; сравнение по нормализованной форме (`normalizeForComparison`: lower-case, `ё`→`е`, пунктуация → пробел, сжатие пробелов, trim). Поиск по тексту карточек в итерации 1 не реализуется (SPEC не требует; при появлении — отдельный ADR/правка).
- **Фильтры (на уровне наличия карточек в колоде):**
  - `all` — все активные колоды (независимо от карточек);
  - `withNewCards` — `newCards > 0` (`state = new`);
  - `inProgress` — `inProgressCards > 0` (`state ∈ {learning, relearning}`; приостановленные карточки в счётчик входят — счётчик информационный, семантика «в процессе изучения»);
  - `due` — `dueCards > 0`; `dueCards`: `due <= now AND suspended = 0 AND (buried_until IS NULL OR buried_until <= now)`; приостановленные и отложенные не считаются просроченными.
- **Архив:** `archived_at != null` — колода скрыта из основного списка (`includeArchived = false` по умолчанию); свайп влево архивирует с undo-снекбаром («Колода в архиве. Отменить») — undo снимает `archived_at`. Отдельного экрана/чипа «Архив» в SPEC A6.2 нет — не добавляем (нет мёртвых кнопок); восстановление до закрытия снекбара — единственный путь возврата (осознанно, до появления архива в post-MVP).
- **Счётчики** (`DeckSummary`): `total`, `new`, `inProgress`, `due`. Считаются одним SQL-запросом репозитория; при подписке на стрим значения фиксируются на момент эмита — drift не переизлучает по времени. UI переподписывается при возврате на экран; долгоживущая подписка без действий может показывать устаревшие `due` (известное ограничение L10).

### 3. Границы итерации 1 на экранах

- «Колоды»: реализованы все элементы A6.2, которые работают без последующих итераций; **не отрисованы** (не мёртвые) «Сгенерировать карточки» (3c), «Продолжить обучение»/сессия (2), «Статистика» в меню (7).
- «Колода»: минимальный A6.3 — заголовок, счётчики, список карточек (без тапа: редактирование — итерация 2), меню Переименовать/Экспорт/Удалить; «Добавить»/«Сгенерировать»/«Начать сессию» не отрисованы до своих итераций.
- Дублирование строковых путей `/decks/<id>` в экранах и роутере — осознанно на итерацию 1 (вынос констант — улучшение без блокировки).

## Последствия

**Плюсы:** M3E подтверждён живьём на первом экране; GoRouter сохраняется; семантика списка зафиксирована и покрыта тестами репозитория и widget-тестами; никаких мёртвых элементов UI.

**Минусы/риски:** (а) `M3EMaterialApp` недоступен, пока библиотека не поддержит `routerConfig` — следить за релизами, при обновлении пересмотреть; (б) устаревание `due`-счётчиков при открытом экране (L10); (в) поиск только по имени колоды — при необходимости расширить; (г) архитектура M3E-слоя остаётся заменяемой: экраны используют только `lib/ui/m3e/m3e.dart`.
