# ADR-031 — Промпт `gen-ru-v6`, обязательная картинка, цепочка провайдеров и заглушки

**Дата:** 2026-11-16 · **Итерация:** 7.14 · **Статус:** принято

## Контекст

Владелец: генерация без файлов и картинки из документов работают, но промпт
`gen-ru-v5` запрещает искать картинки для абстрактных понятий, и у большинства
карточек картинок нет. Цель — **уместная картинка у каждой карточки**: она
помогает запоминанию (active recall + образ).

Ограничения проекта: локаль только `ru` (один ARB), схема БД не должна
ломаться без миграции, ключи API — только `--dart-define`/env, сеть в тестах —
только мок-клиент, «ничего не ломай в Классике, Ленте и Тренировке».

Проблемы текущей реализации (7.12–fix-gen):

- `image_query` — nullable строка; правило «абстрактным понятиям null»
  отбрасывает большую часть карточек;
- цепочка — `CompositeCardImageFinder` из трёх «сервисов», каждый сам качает и
  фильтрует; нет единого таймаута на провайдера, фильтра размеров/пропорций,
  дедупликации URL, метаданных атрибуции, фолбэк-запроса;
- если картинки нет, карточка остаётся пустой; в UI нет полноэкранного
  просмотра и атрибуции; поиск блокирует показ колоды.

## Решение

### 1. Схема ответа: обязательный объект `image` (`gen-ru-v6`)

У каждой карточки — объект `image`:

```json
"image": {
  "query": "3–7 английских слов",
  "fallback_query": "2–4 слова, более общий",
  "kind": "photo" | "diagram" | "illustration"
}
```

- v6 — новый промпт; v5 не удалён (исторические колоды/тесты байт-в-байт),
  переключение версии — `systemPromptVersion = 'gen-ru-v6'` и константа
  `systemPromptGenRuV6` (`lib/api/prompts/system_prompt.dart`); дословная копия —
  `docs/prompts/gen-ru-v6.txt`.
- Строгая схема провайдера (`canonicalCardsResponseSchema`) требует `image`;
  локальная поштучная схема (`localCardItemSchema`) **терпима**: принимает и v6,
  и v5 (`image_query` строкой/`null`), обязательны только `front`, `back`,
  `card_type`. Одна плохая карточка по-прежнему отбрасывается сама.
- Нормализация (`lib/api/generation/image_query_normalizer.dart`): убрать
  `image/picture/photo of`, имена файлов, LaTeX, не-латиницу; обрезать до 7 слов;
  пустой запрос собрать из `fallback_query`; одно слово дополнить контекстом
  вида. Правка → `CardIssueCode.imageQueryAdjusted`, карточка остаётся.
- Правило «абстрактным понятиям картинка не нужна» удалено; `kind` выводится из
  текста только для legacy-ответа v5.

### 2. Провайдеры: интерфейс и цепочка

- `ImageProvider` (`lib/api/images/image_provider.dart`) — только **поиск**:
  возвращает кандидатов (`url`, автор, лицензия, атрибуция, размеры). Провайдеры:
  Wikimedia Commons → Wikipedia pageimages (семейство Wikimedia, ADR-028) →
  Openverse → Pixabay/Pexels **только при ключе**.
- `ImageSearchService` — цепочка (`implements CardImageFinder`): таймаут ~6 с на
  провайдера, бюджет 20 с на карточку, основной запрос затем `fallback_query`,
  скачивание через общий ограничитель (≤ 4 параллельно), проверка MIME
  (JPEG/PNG/WebP), короткой стороны ≥ 400 px и соотношения сторон ≤ 3:1,
  безопасный поиск (запросы провайдеров), кэш «запрос+вид → картинка» (LRU,
  32 записи), один ретрай с backoff на 429/5xx, затем следующий провайдер.
  Набор занятых URL ведёт вызывающий (пайплайн), цепочка его только читает.
- Ключи Pixabay/Pexels — `String.fromEnvironment`/`Platform.environment`, без
  ключа провайдера в цепочке нет.

### 3. Заглушка, если картинки нет

- `PlaceholderImageGenerator` — PNG 800×450 (схема 800×600) из 8 пар цветов,
  детерминированно от seed (хэш содержимого карточки: id появляется только при
  импорте). Рисуется градиент + геометрический паттерн + иконка вида.
- Заглушка пишется в `MediaStore` вместе с метаданными (`<путь>.meta.json`:
  `provider`, `sourceUrl`, `author`, `license`, `isPlaceholder`, `query`,
  `fallbackQuery`, `kind`). Схема БД **не меняется**: метаданные — побочный
  JSON-файл; GC удаляет его вместе с медиа.
- «Найти картинку заново» в редакторе карточки (`CardImageRefresher`) и фоновый
  ретрай заглушек на старте (`main.dart`, ≤ 5 за запуск, ошибки глушатся).
- Пожелание «без картинок» отключает и поиск, и заглушку.

### 4. UI

- Общий `CardImageView`: 16:9 (схема 4:3), `cover` для фото/метафоры,
  `contain` на нейтральном фоне для схемы, скругление 16 (токен M3 large),
  fade-in, скелетон, ограничение высоты 220 px — текст и LaTeX не вытесняются.
- Тап — полноэкранный просмотр с `InteractiveViewer` (зум до 5×) и атрибуцией
  (автор, лицензия, ссылка). Картинка используется в предпросмотре генерации,
  Классике, Ленте, Тренировке и редакторе карточки.
- Поиск картинок не блокирует показ: пайплайн отдаёт карточки сразу после
  ответа модели и присылает прогресс-снимки (`GenerationProgress.cards`), а
  изображения догружаются; экран генерации показывает живой список.

## Последствия

- + Картинка у каждой карточки; предсказуемая атрибуция; тестируемая цепочка.
- − Метаданные атрибуции лежат рядом с файлом, а не в БД: при ручной чистке
  каталога `media/` их можно потерять (карточка останется с картинкой без
  атрибуции). `MediaStore` поддерживает `readMetadata`/`writeMetadata`.
- − Заглушка генерируется до импорта от хэша содержимого, а не от id: правка
  текста карточки меняет заглушку (одна карточка — одна картинка до правки).
- − `deepseek-flash`/строгие провайдеры могут не соблюдать `image` (L80):
  локальная терпимая схема сохраняет карточку, картинка будет заглушкой.
- Пин сторонних зависимостей не менялся.
