# ADR-022 — Гибридная обработка вложений: локальный текст + Vision только там, где модель его поддерживает

**Дата:** 2026-11-15 · **Итерация:** 7.8 · **Статус:** принято

## Контекст

SPEC A8.3 описывает только локальный текстовый парсинг документов. Владелец поставил
требование: приложение должно работать с **любой** моделью (OpenAI, Gemini, Anthropic,
DeepSeek, локальные), а прямая загрузка файлов поддерживается провайдерами по-разному.
Причины:

1. Word-файлы с управляющими символами (`\x00`, `\x0B`) приводили к отказу API
   «invalid characters in content», а пользователь видел общее сообщение.
2. Изображения (JPG/PNG) и PDF-сканы не принимались генерацией вовсе.
3. Модели без Vision не должны получать картинки; модели с Vision не должны терять
   возможность работать с ними.
4. Причина HTTP 400 от провайдера не доходила до UI.

## Варианты

| Вариант | Оценка |
|---|---|
| **A. Только текст (как было)** | ломает картинки и сканы; не отвечает owner note |
| **B. Всегда Vision** | модели без Vision получают 400; локальные текстовые модели перестают работать |
| **C. Прямая загрузка файлов через file API каждого провайдера** | разные API (OpenAI Files, Gemini File API, Anthropic Files), ключи/хранение, лишние сетевые шаги; не для локальных серверов |
| **D. Гибрид: текст локально, изображения — inline при Vision (выбрано)** | любая модель работает с текстом; картинки/сканы — только при явной поддержке; один путь для облака и локальных серверов |

## Решение

1. **TextSanitizer** (`lib/domain/text/text_sanitizer.dart`) — единый санитайзер
   локально извлечённого текста: удаляет управляющие символы (кроме `\t`/`\n`),
   нормализует переводы строк, сжимает пустые строки, обрезает пробелы.
   `normalizeDocumentText` делегирует в него; `CardGenerationService` повторно
   санитизирует материалы и пожелания. Пустой текст без вложений → `noMaterials`
   до сборки запроса (сеть не вызывается). ARB: «В файле нет текста (скан или пустая форма)».
2. **`supportsVision`** — поле модели каталога (`ProviderPresetModel.supportsVision`)
   и аккаунта (`ProviderAccount.supportsVision`, JSON `supports_vision`). Дефолты:
   OpenAI GPT-4o/4o-mini, Gemini Flash, Anthropic Claude 3.5, OpenRouter GPT-4o/Claude —
   `true`; DeepSeek Chat/Reasoner, Moonshot 8K, MiniMax Text, Groq Llama, Ollama
   llama/qwen — `false`. Старые записи без поля: модель пресета, иначе инференс по
   имени (`gpt-4o`, `claude`, `gemini`, `flash`, `vision`, `vl`, `llava`) — аккаунт
   владельца `deepseek-flash` получает `true`, `deepseek-chat`/`qwen2.5` — `false`.
   В диалоге «Пользовательская модель API» — переключатель «Модель принимает изображения».
3. **Маршрутизация (API-слой)** для каждого фрагмента:
   - непустой текст → текст (любая модель);
   - картинка JPG/PNG + `supportsVision=true` → image part base64;
   - картинка + `supportsVision=false` → `visionUnsupported` («Модель не поддерживает изображения»);
   - PDF-скан + Vision + протокол принимает PDF (Anthropic `document`, Gemini
     `inlineData application/pdf`) → PDF-part;
   - PDF-скан без Vision → `fileWithoutTextAndVision`; Vision без PDF-протокола →
     `pdfScanUnsupported`;
   - вложение больше 10 МБ → `attachmentTooLarge`.
   OpenAI Chat Completions и OpenAI-совместимые серверы получают только `image_url`;
   PDF туда не отправляется (нет стандартного inline PDF в этом протоколе).
4. **Пайплайн**: текст режется как раньше; каждый файл-вложение — отдельный фрагмент
   (1 файл = 1 запрос), имя входит в `generation_jobs.files` и `sourceFiles`; при
   ошибке вложение сохраняется в `GenerationChunkFailure` для повтора. Схема БД не меняется.
5. **Ошибки 400**: `GenerationHttpClient` извлекает `error.message`/`message`/`detail`
   из тела 4xx, очищает управляющие символы, редактирует секретоподобные значения,
   ограничивает 200 символов и кладёт в `GenerationException.providerReason`.
   UI показывает ARB-шаблон «Запрос отклонён: {reason}»; тела запросов/ответов
   по-прежнему не логируются. Это осознанное исключение из правила «только ARB»:
   владелец требует реальную причину; текст причины — не ключ и не материалы,
   а серверное объяснение.
6. **UI**: picker принимает JPG/JPEG/PNG; картинка не парсится; PDF без текстового
   слоя сохраняется как скан-вложение; перед запуском проверяются `supportsVision`
   и PDF-возможность протокола выбранного аккаунта.

## Последствия

- Текст работает с любой моделью, включая локальные серверы без Vision.
- Картинки/сканы работают только у моделей с явно включённым Vision; ошибки понятны.
- PDF-скан у OpenAI/OpenAI-совместимых не отправляется — отдельная ошибка; рендер
  страниц в изображения и OCR — post-MVP.
- Inline-base64 увеличивает тело на ~33 %; лимит 10 МБ на файл.
- Инференс Vision по имени модели может ошибаться; пользователь исправляет
  переключателем в настройках, ошибка 400 показывает причину.
- Живые Vision-вызовы облачных провайдеров не проверялись (нет ключей) — L52.
