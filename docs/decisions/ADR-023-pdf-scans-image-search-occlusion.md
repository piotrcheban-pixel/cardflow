# ADR-023 — PDF-сканы через рендер страниц, поиск иллюстраций и wire-формат occlusion

**Дата:** 2026-11-15 · **Итерация:** 7.9 · **Статус:** принято

## Контекст

Итерация 7.8 научила приложение отправлять PDF-скан как документ (только Anthropic/Gemini),
но владелец указал три оставшихся сценария:

1. PDF-сканы не работают у моделей с Vision, которые не принимают PDF (OpenAI и
   OpenAI-совместимые): раньше это была ошибка `pdfScanUnsupported`.
2. Лента показывала отзеркаленный текст обратной стороны карточки из-за 3D-переворота.
3. Генерация не могла добавить к карточке иллюстрацию из интернета и не поддерживала
   формат occlusion, выбранный моделью.

Ограничения: SPEC A5 прямо говорит, что occlusion — **не тип карточки**, а разметка
внутри `basic`; схема БД и формат экспорта публичны и в этой итерации меняться не должны.
Ключей сторонних API у проекта нет, платные сервисы не рассматриваются.

## Варианты

### PDF-сканы

| Вариант | Оценка |
|---|---|
| **A. Оставить PDF-part (7.8)** | OpenAI/совместимые по-прежнему не работают; owner note не выполнен |
| **B. OCR локально** | тяжёлые зависимости/модели, качество и оффлайн-размер; вне MVP |
| **C. Рендер первых страниц PDFium → PNG → image parts (выбрано)** | работает у любой Vision-модели, проверено PDFium'ом pdfrx; страницы одного PDF — один запрос |
| **D. Внешний сервис конвертации** | сеть, приватность, ключи, лишняя зависимость |

### Поиск картинок

| Вариант | Оценка |
|---|---|
| **A. Генерация картинок моделью** | запрещено owner note — картинки должны искаться, а не генерироваться |
| **B. Unsplash/Pexels API** | требуют ключа и регистрации; ключ пришлось бы хранить и настраивать |
| **C. Openverse API (выбрано)** | открытый эндпоинт без ключа, только CC0/PDM/CC BY/CC BY-SA, отдаёт готовый thumbnail и атрибуцию; анонимный лимит ~1 req/s |
| **D. Wikimedia Commons API** | без ключа, но сырые оригиналы и более громоздкий разбор; Openverse проще и уже агрегирует Commons/Flickr |

### Occlusion

| Вариант | Оценка |
|---|---|
| **A. Новый `CardType.occlusion`** | противоречит SPEC A5, ломает экспорт/редактор/фильтры; schemaVersion не нужен, но публичный контракт меняется |
| **B. Wire-значение `card_type: "occlusion"` только в ответе модели, в приложении — `basic` + `occlusion_json` + media (выбрано)** | соответствует SPEC A5, БД/экспорт не меняются, ручной редактор масок работает как раньше |
| **C. Игнорировать occlusion** | owner note не выполнен |

## Решение

1. **PDF-скан → PNG-страницы.** Если PDF-парсер извлёк меньше 50 символов текста или
   поднял `scannedPdf`, `GenerationScreen` вызывает `FileParsingService.renderPdfPages`.
   `PdfScanRenderer` (`lib/api/parsers/pdf_scan_renderer.dart`) на PDFium (pdfrx) рендерит
   первые **не более 4** страниц в PNG (2× от 72 dpi, ширина ≤ 1600 px) и кодирует
   `package:image`; рендер выполняется в изоляте, как и парсинг (A8.3). Страницы одного
   PDF получают общий `groupKey` и уходят **одним** фрагментом (несколько image parts);
   `generation_jobs.files` содержит имя PDF один раз. Модель без Vision получает
   `pdfScanVisionRequired` («PDF-скан без текста. Выберите модель с поддержкой изображений»).
   Если рендер не удался — fallback на PDF-документ для Anthropic/Gemini (поведение 7.8),
   иначе — прежние `fileWithoutTextAndVision`/`pdfScanUnsupported`. Порог 50 символов —
   константа `kPdfScanMinTextLength` в `generation_screen.dart`.
2. **Поиск иллюстраций.** Схема ответа `gen-ru-v3` добавляет
   `image_query: string|null` (обязательное поле strict-схемы, краткий запрос на
   английском), `card_type` получает значение `occlusion`. `ImageSearchService`
   (`lib/api/images/`) реализует доменный порт `CardImageFinder`: GET
   `https://api.openverse.org/v1/images/?q=…&page_size=5&license=cc0,pdm,by,by-sa&mature=false`,
   затем скачивание `thumbnail` (fallback — `url`), проверка сигнатуры JPEG/PNG, размер
   ≤ 5 МБ, User-Agent `CardFlow/1.0`, троттлинг 1 запрос/с. Ключ не нужен, настройки
   не меняются; любая ошибка сети/API → `null` (карточка остаётся без картинки).
3. **Пайплайн и медиа.** `GenerationPipeline` после дедупликации разрешает `image_query`
   через `imageFinder`, кэшируя результат в рамках запуска; байты кладутся в
   `GeneratedCard.image` (`GeneratedCardImage`: bytes, MIME, query, sourceUrl, attribution).
   Файл и строка `media` пишутся **при импорте** — `DriftGenerationCardStore` (только для
   выбранных пользователем карточек), `cards.media_json` = `[media.id]`. Ошибка поиска
   или `imageFinder == null` не отменяет карточку.
4. **Occlusion.** Валидатор проецирует wire `occlusion` в `CardType.basic` +
   `GeneratedCard.isOcclusion = true`; с найденной картинкой пайплайн ставит
   `occlusion_json` v1 с прямоугольной маской по центру (`x=0.3, y=0.35, w=0.4, h=0.3`;
   `defaultOcclusionDocumentJson`). Без картинки карточка понижается до `basic`,
   добавляется пометка `occlusionImageMissing`, маска не пишется. В БД и экспорте
   карточка всегда `basic` с `occlusion_json` — SPEC A5 соблюдён, `schemaVersion` и
   `format_version` не менялись.
5. **UI.** Обычная карточка с `media` показывает иллюстрацию над текстом
   (`CardContentView`), occlusion — прежний `OcclusionImageView`; предпросмотр
   показывает миниатюру, подпись «Изображение с маской» и пометку отсутствия картинки.
6. **Лента.** Для обратной стороны 3D-переворота добавляется второй
   `Matrix4.rotationY(pi)`, поэтому текст читается слева направо (m00 > 0).

## Последствия

- PDF-сканы работают у OpenAI/OpenAI-совместимых Vision-моделей; Anthropic/Gemini
  по-прежнему могут получить исходный PDF при сбое рендера.
- Скан рендерится максимум 4 страницы: дальние страницы в запрос не попадают (A8.5
  фрагментация и так ограничивает объём); при необходимости вторая генерация с новым
  фрагментом — post-MVP.
- Openverse анонимный лимит ~1 запрос/с: сервис троттлит поисковые запросы; при 429
  карточка остаётся без картинки. Кэш по запросу снижает число вызовов.
- Байты иллюстраций живут в памяти до импорта; на фрагмент не больше 20 карточек,
  thumbnail ≤ 5 МБ. Отдельного дискового кэша поиска нет.
- Атрибуция CC хранится в `GeneratedCardImage.attribution` в памяти, но в БД не
  переносится: в схеме `media` нет поля метаданных (менять схему в MVP нельзя).
  Изображения используются локально для личных учебных карточек; это ограничение L58.
- `image_query` увеличивает ответ модели; strict-схема требует поле у всех карточек.
  Провайдеры, не следующие схеме, получат `invalidResponse` — как и раньше для других
  обязательных полей.
- Новый runtime-пакет: `image ^4.12.0` (MIT, чистый Dart) — был транзитивным через
  `pdfrx_engine` и теперь объявлен явно (ADR-023, `docs/dependencies.md` §14).
