# ADR-009 — Ручное создание и редактирование карточек: поля, типы, валидация, удаление

**Дата:** 2026-11-13 · **Итерация:** 2 · **Статус:** принято
**Контекст SPEC:** A6.3 (форма новой карточки, тап по карточке → редактирование), A5 (`cards`, `basic_reversed` = две строки с взаимными `sibling_id`, `content_hash`, `source_excerpt` при ручном создании «по желанию»), A7.9/A7.8/A7.10 (cloze/occlusion/LaTeX — итерации 5), A8.4 (локальный валидатор: front ≤500, back ≤2000, теги ≤3 без `#`), L14 (длины при импорте).

## Контекст

До итерации 2 карточки появляются только импортом `.zip`. Нужна ручная форма создания/редактирования, но SPEC не уточняет: какие типы карточек доступны сразу, можно ли менять тип при редактировании, что происходит с парной карточкой при удалении, обязателен ли `back`, какие ещё поля показывать.

## Решение

- **Поля формы:** `front` (обязателен, ≤500), `back` (обязателен для `basic`/`basic_reversed`, ≤2000), `hint` (необязателен), `tags` (строка через запятую: trim, убрать `#`, пустые и дубликаты, ≤3 — A8.4), `source_excerpt` (необязателен, ≤400, для кнопки «Почему?»), тип карточки.
- **Типы в форме:** `basic` и `basic_reversed`. `basic_reversed` создаёт **две** строки `cards` с взаимными `sibling_id`, вторая — с переставленными `front`/`back`; `content_hash` считается для каждой строки по её собственным сторонам. `cloze` в форме не предлагается: сначала нужен редактор разметки `{{c1::…}}` (итерация 5) — иначе пользователь получит нерабочую карточку.
- **Тип неизменяем на редактировании.** Смена типа потребовала бы создать/удалить парную строку, пересобрать `sibling_id` и историю повторений; в итерации 2 форма показывает тип только для чтения при edit.
- **Удаление:** одна строка; у парной `basic_reversed`-карточки `sibling_id` обнуляется (пара распадается, вторая карточка остаётся самостоятельной). Удаление — с диалогом подтверждения; каскадного удаления пары нет (осознанно: пользователь может хотеть оставить одну сторону).
- **`content_hash`** пересчитывается при создании и любом изменении `front`/`back`.
- **Транзакции:** создание `basic_reversed` — обе строки в одной транзакции; редактирование/удаление — одна транзакция на операцию.
- **Редактирование из сессии** («Изменить», A7.2 — «дополнительно») в итерации 2 не отрисовано: backlog итераций 5/6.
- **Свайп-удаление/приостановка карточки в списке колоды** (A6.3) отложены до появления приостановки в конструкторе (итерация 6); удаление доступно из формы карточки.

## Последствия

- Ручные карточки сразу имеют корректный `content_hash`, поэтому дедупликация импорта/генерации (A8.5) работает и для них.
- `basic_reversed` даёт две независимые единицы повторения — как и требует A5 (у каждой своё состояние FSRS).
- Импортированные карточки типов `cloze`/`basic_reversed` редактируются той же формой как текст (`cloze`-разметка `{{c1::…}}` сохраняется как есть): специализированный редактор масок/разметки с предпросмотром — итерация 5, но тап по карточке не «мёртвый» уже сейчас. В сессии классического режима `cloze`-карточка до итерации 5 показывается как обычный текст (рендер пропусков — итерация 5).
- Ограничения длины не применяются к импорту (L14 остаётся для импорта; ручное создание валидируется).
