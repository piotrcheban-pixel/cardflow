# ADR-026 — Инвариант новой карточки: `due` и `fsrs_json` при создании

**Дата:** 2026-11-15 · **Итерация:** 7.11 · **Статус:** принято

## Контекст

Owner note 7.11: после генерации карточек «Начать сессию» показало «Нет карточек к
повторению», хотя карточки не оценивались. Диагностика по фактической БД приложения:

- 43 карточки `state = 'new'`, у **всех** `due IS NULL` и `fsrs_json IS NULL`;
- за день 30 оценок «новых» карточек (`actual_days IS NULL`) при `daily_new_limit = 20`;
- значит `ReviewQueue.build(..., newLimit: 0)` пуст, а проверка на экране колоды шла
  **без** лимитов и пропускала в пустую сессию.

Корневая причина пустой сессии — исчерпанный дневной лимит (закрыт ADR-025 и
причиной в пустом состоянии). Отдельный дефект — неполная строка новой карточки:
`due = NULL` означает «не запланирована», и любой запрос «что учить сейчас» по `due`
её не видит.

## Варианты

| Вариант | Оценка |
|---|---|
| **A. Оставить `due = NULL` у новых** | SPEC A5 формально допускает (`due` nullable), но инвариант разъезжается: очередь знает про `state`, а счётчики/фильтры по `due` — нет; повторение бага вероятно |
| **B. Заполнять `due = now` и `fsrs_json` начального состояния (выбрано)** | строка сразу целостная, `CardSchedulingMapper` разбирает её без ветки «а если new»; `state = 'new'` остаётся источником правды для «новизны» |
| **C. Запретить `due` у новых на уровне схемы** | миграция и ломает импорт чужих колод с `due` у `new` |

## Решение

1. `CardSchedulingMapper.initialScheduling(cardId, now)` возвращает
   `SchedulingCard.newCard` (state `new`, шаг 0, без истории).
2. `DriftCardRepository.createCards` и `DriftGenerationCardStore` пишут
   `due = now` и `fsrs_json` этого снимка. `state` остаётся `new` — «новизну»
   определяет состояние, а не отсутствие `due`.
3. Потребители, которые раньше опирались на `due IS NULL`, переводятся на `state`:
   - счётчик «к повторению» (`DriftDeckRepository`): `AND c.state <> 'new'`;
   - базовый порядок конструктора (`SessionBuilder._baseOrder`): запланированные —
     по `due`, новые — по `createdAt`.
4. Причина пустой сессии — отдельный экран/сообщение (`reviewDailyLimitTitle`),
   потому что лимит A6.6 остаётся продуктовым правилом; тренировка (ADR-025) даёт
   обход, не ломая FSRS.

## Последствия

- `ReviewQueue`, `CardSchedulingMapper` и FSRS-слой видят новую карточку как валидную
  запись; `fsrs_json` разбирается без `null`-ветки.
- Экспорт/импорт `.zip`, `schemaVersion` и `format_version` не меняются: поля
  `due`/`fsrs_json` в SPEC A5 уже есть.
- Счётчик «к повторению» семантически соответствует A7.2 («просроченные, кроме new»);
  ранее это совпадало случайно, пока у новых `due` был `NULL`.
- Импорт колод, где `state = 'new'` с `due`/`fsrs_json` — работает как раньше
  (данные не перезаписываются).
- Ограничение: у новых карточек `due` = момент создания и сдвигается только оценкой;
  «время появления в очереди» по-прежнему задаёт лимит, а не `due`.
