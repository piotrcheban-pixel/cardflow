# ADR-015 — Пайплайн генерации: бюджеты токенов, чанкинг, задания и импорт (итерация 3c)

**Дата:** 2026-11-14 · **Статус:** принято · **Связано:** SPEC A6.8, A8.1–A8.6, A5; ADR-003, ADR-011,
ADR-012, ADR-013, ADR-014; `docs/generation-pipeline.md`

## Контекст

Слой 3b умеет: собрать промпт `gen-ru-v2`, вызвать одного провайдера на один фрагмент, проверить ответ
канонической схемой A8.4 и контентными правилами, ретраить 429/5xx/таймауты, редактировать логи. Экран
A6.8 и пайплайн A8.5 остались на 3c. SPEC требует: локальную оценку токенов, нарезку текста по границам
разделов с запасом под ответ, последовательные вызовы с прогрессом/отменой, дробление обрезанного
фрагмента один раз, дедупликацию между фрагментами и с существующей колодой, предпросмотр с
редактированием, импорт одной транзакцией и `generation_jobs` на каждом шаге.

Ограничения, которые нельзя нарушить:

- **3.4/A8.6:** ключи — только `ApiKeyStore`; материалы и ответы модели не логируются и не попадают в
  `generation_jobs`.
- **A8.4:** карточка с пометкой не отбрасывается — предпросмотр показывает и даёт исправить.
- **A8.5 шаг 6:** фрагменты отправляются **последовательно** (без параллельных запросов).
- **A8.5 шаг 8:** при обрезании — деление пополам и **один** повтор; дальше ошибка фрагмента с повтором.
- **A6.8:** у пользователя нет поля «сколько карточек»; ограничение ответа задаётся пайплайном.

## Варианты

1. **Отдавать модели весь текст одним запросом** — просто, но упирается в контекст модели, ответ
   обрезается на больших материалах; противоречит A8.5 шаг 5. Отказ.
2. **Резать по символам фиксированного размера** — рвёт разделы (заголовок отдельно от текста), теряет
   смысловые границы; A8.5 требует границы разделов. Отказ.
3. **Нарезка по разделам `ParsedDocument` с жёстким делением oversized-раздела и бюджетом модели** —
   сохраняет структуру, укладывается в контекст. Выбрано.
4. **Отдельный серверный/фоновый воркер** — вне MVP, нет сервера (3.2). Отказ.

## Решение

### 1. Оценка токенов и бюджеты моделей

- `TokenEstimator` (`lib/domain/generation/token_estimator.dart`) — эвристика для русского текста:
  `ceil(количество Unicode-символов / 2.5)`. Это **оценка** для UI и нарезки, а не биллинг: фактический
  расход берётся из `usage` ответа провайдера (`GenerationResult.usage`).
- Каталог моделей `GenerationModel` (`lib/domain/generation/generation_model.dart`): `id`, отображаемое
  имя, провайдер, `contextTokens`. Встроенные провайдеры (OpenAI/Gemini/Anthropic) получают статический
  каталог — это данные приложения, а не вызов API; список можно уточнять без изменения контрактов.
  OpenAI-совместимый сервер списка не имеет (ADR-013): модель берётся из `app_settings`, бюджет —
  консервативный [`kCompatibleInputTokenBudget = 16000`].
- Бюджет входа на фрагмент = `contextTokens − maxOutputTokens (8192) − оценка системного промпта и
  обёртки − 512` (запас). Минимум — 2000 токенов; если модель не найдена, используется консервативный
  бюджет 8000.
- «Примерно N токенов» = оценка входных токенов + оценка выхода по `<limit>`; при превышении порога
  (100 000 входных токенов) показывается предупреждение, генерация не блокируется.

### 2. Чанкинг

- `GenerationChunker` (`lib/domain/generation/generation_chunker.dart`) берёт разделы `ParsedDocument`
  (`ParsedSection.start/end`), склеивает соседние разделы, пока оценка ≤ бюджета; между разделами —
  ровно пустая строка (инвариант `ParsedDocument`).
- Раздел больше бюджета делится по абзацам (пустая строка), затем по строкам, затем жёстко по символам
  с запасом 20 %. Текст не теряется: объединение чанков содержит все непустые разделы в исходном порядке.
- `<limit>` на фрагмент — `min(kMaxCardsPerChunk = 20, ...)`: ответ не должен обрезаться из-за большого
  числа карточек; `maxOutputTokens = 8192` остаётся верхней границей.
- Для `truncated` чанк делится пополам по тем же правилам (`splitInHalf`) один раз; каждая половина
  помечается `splitAttempted = true`. Повторный `truncated` — ошибка фрагмента.

### 3. Пайплайн и ошибки

`GenerationPipeline` (`lib/api/generation/generation_pipeline.dart`):

1. Создаёт задание `generation_jobs` (`status = running`, файлы — **только имена**, prompt_version).
2. Оценивает токены и режет материал; пустой результат — `noMaterials` (новый код, строка ARB).
3. Идёт по фрагментам **последовательно**: `sending(chunk K из M)` → вызов
   `CardGenerationService.generate` → `receiving` → накопление карточек/токенов.
4. После каждого фрагмента обновляет задание (`chunk_count`, `cards_count`, `tokens_used`).
5. `truncated` → split-once (см. §2). `cancelled` → статус `cancelled`, возвращаются уже полученные
   карточки. Fatal-коды (`missingApiKey`, `providerNotConfigured`, `invalidApiKey`) останавливают
   пайплайн (повторять один и тот же отказ на каждом фрагменте бессмысленно); остальные ошибки —
   частичный успех: фрагмент попадает в `failures`, обработка продолжается (A6.8).
6. Дедупликация: `contentHashOf(front, back)` по нормализации A5; множество включает существующие
   карточки целевой колоды и уже принятые карточки. Для `basic_reversed` проверяются оба направления
   (`front/back` и `back/front`), чтобы не создать дубль парной карточки.
7. Итоговый статус: `done` (нет ошибок), `partial` (есть карточки и ошибки), `error` (карточек нет),
   `cancelled`. `error_code` — первый код ошибки (машинный, не текст).
8. `retryFailed` повторяет только фрагменты из `failures` (и их текст), новые карточки дедуплицируются
   с уже принятыми; статус задания пересчитывается.

### 4. Предпросмотр и импорт

- Результат пайплайна — неизменяемый `GenerationRunResult` (карточки, ошибки, токены, число дублей,
  отменён ли). UI предпросмотра хранит редактируемые копии `GeneratedCard` (front/back/tags), чекбоксы.
- Импорт — `GenerationCardStore.importGeneratedCards` (`lib/domain/generation/generation_card_store.dart`,
  реализация — `lib/data/generation/drift_generation_card_store.dart`):
  - одна транзакция; при ошибке — откат;
  - целевая колода есть → карточки добавляются; нет → создаётся колода с переданным именем;
  - дедупликация повторяется **внутри** транзакции (защита от гонки и повторного импорта);
  - `basic_reversed` создаёт две строки с взаимными `sibling_id` (SPEC A5);
  - `generation_jobs.result_deck_id` и `cards_count` обновляются в той же транзакции.
- Имя колоды по умолчанию (пустое поле) вычисляет UI: имя первого файла без расширения, иначе строка ARB
  «Сгенерированные карточки». Для существующей колоды поле имени скрыто — имя не меняется.

### 5. Файлы и drag-n-drop

- `DocumentGateway` (`lib/domain/generation/document_gateway.dart`) — узкий контракт пикера и чтения;
  реализация `FilePickerDocumentGateway` использует `file_picker 13.3.3` (`pickFiles`, multiple,
  `allowedExtensions` форматов A8.3) и читает `dart:io` с проверкой 25 МБ **до** чтения в память.
- Drag-n-drop — `desktop_drop 0.8.4` (`DropTarget`) только в UI; на мобильных событий нет, работает
  пикер. Версия зафиксирована из-за конфликта `cross_file` (`docs/dependencies.md` §7); API стабилен,
  L8 остаётся ограничением «0.8.4 вместо 0.9.x».
- Парсинг файлов — существующий `FileParsingService` (изолят, ошибки по файлу); UI показывает статусы
  `parsing/parsed/failed` и строку ошибки из ARB.

### 6. Ключи облачных провайдеров

A6.8 требует: «если ключ не задан — кнопка ведёт в настройки». До итерации 7 экрана ключей нет, поэтому
в 3c на экране «Настройки генерации» добавлен блок **«Ключи API»** для OpenAI/Gemini/Anthropic: статус
«ключ сохранён/не задан», поле ввода (obscured) и сохранение/удаление через `ApiKeyStore`. Сетевая
проверка ключа («Проверить», A6.6) остаётся итерации 7 — кнопка не рисуется (нет мёртвых кнопок).
Кнопка «Ключ не задан» на экране генерации ведёт на `/settings/generation`.

### 7. Что не меняется

- Каноническая схема, адаптеры, retry/backoff, redaction, `ApiKeyStore`, `CardGenerationService` — без
  изменений; пайплайн вызывает сервис через узкий интерфейс `GenerationCaller`.
- Промпт `gen-ru-v2` и его версия; она пишется в `generation_jobs.prompt_version`.
- Схема БД (`schemaVersion = 1`): таблица `generation_jobs` уже создана в итерации 1.

## Последствия

- Пользователь получает полный поток A6.8: файлы → пожелания → провайдер/модель → оценка → генерация с
  прогрессом/отменой → предпросмотр → импорт.
- Большие документы не упираются в контекст; цена — несколько последовательных запросов и возможный
  частичный успех, который виден пользователю и повторяем.
- Оценка токенов приблизительная (эвристика, а не токенизатор модели); фактический расход показывается
  из ответа. Живые контракты OpenAI/Gemini/Anthropic не проверены (L1); DeepSeek success-путь — 3b/L30.
- Список моделей статический; при устаревании имён — правка каталога без миграций (ADR-015 §1).
- `generation_jobs` не хранит материалы и ключи — только имена файлов и машинные коды.
