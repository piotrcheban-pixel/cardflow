# ADR-030 — Изображения из документов, причины сбоя фрагментов и частичный импорт

**Дата:** 2026-11-15 · **Итерация:** fix-gen · **Статус:** принято

## Контекст

Приёмка владельца (Д1–Д6) после ручной проверки генерации:

- **Д1** — генерация без файлов не работает (только тема/пожелание);
- **Д2** — картинки часто не подходят к вопросу (шар для аксиомы статики,
  биология для аксиомы связей);
- **Д3** — изображения из прикреплённых файлов не используются;
- **Д4** — формулы отображаются криво (сырой LaTeX или испорченный текст);
- **Д5** — низкое качество карточек (ответ в вопросе, расшифровка букв);
- **Д6** — «Не удалось обработать фрагмент…», после чего «Импортировать» не
  работает.

Диагностика (подробно — `journal/iteration-fix-gen/diagnosis.md`):

- гипотеза JSON-экранирования LaTeX подтверждена фикстурами: `\frac` → form
  feed + `rac`, `\times/\theta` → tab, `\beta` → backspace, `\rho` → CR,
  `\nabla/\neq` → LF, а `\alpha`, `\sum`, `\Delta`, `\cdot` — недопустимый
  escape, `jsonDecode` падает. Это одновременно Д4 (тихая порча) и Д6
  (фрагмент падает с `invalidResponse`);
- валидатор схемы отбрасывал **весь** фрагмент из-за одной карточки, а экран
  предпросмотра не импортировал ничего, если хоть одна карточка не проходила
  `CardDraft.isValid`;
- изображения из документов не извлекались вовсе: `ParsedDocument` не нёс
  изображений, DOCX/PPTX/ODT-парсеры читали только текст; внешний поиск шёл
  по `image_query`, а при его отсутствии — по запросу, выведенному из текста
  вопроса (источник «шара» для аксиомы).

## Решение

1. **Д4/Д6. Восстановление LaTeX.**
   - До `jsonDecode` (`latex_escape_repair.dart`) удваиваются одиночные `\` у
     LaTeX-команд: недопустимые JSON escape — всегда, допустимые
     (`\frac`, `\nabla`, …) — только если хвост образует известную команду
     (`\n` между словами остаётся переносом).
   - После разбора управляющие символы `\f/t/b/r/n` внутри `$…$` с хвостом
     команды восстанавливаются в `\frac/\times/\beta/\rho/\nabla`; разделители
     `\(…\)`/`\[…\]` нормализуются к `$…$`/`$$…$$`, `\$` — не формула.
   - `CardContentView`/`LatexText`/`ClozeText` рендерят сегменты «текст /
     inline / block» через `Math.tex`; ошибка разбора — предупреждение
     «Ошибка разметки формулы», карточка не исчезает.
2. **Д6. Поштучная проверка.** Схема проверяется по каждой карточке
   (`CardResponseSchema.splitValid`), структурно непригодная карточка
   отбрасывается сама (`validator_rejected`), остальные сохраняются.
   У каждой ошибки фрагмента есть внутренний код причины
   (`GenerationFailureReason`: `truncated`, `refusal`, `safety`, `json_parse`,
   `schema_invalid`, `validator_rejected`, `network`, `http_4xx`, `http_5xx`,
   `empty_response`, `provider_response`, `cancelled`, `unknown`); коды пишутся
   в `generation_jobs.error_code` (через запятую) и в debug-лог
   (`GenerationDiagnostics.fragmentFailure`), без текста материалов и ключей.
   Предпросмотр показывает «Фрагмент K из M: понятная причина», импорт
   доступен при частичном успехе; кнопка неактивна только без выбранных
   карточек.
3. **Д3. Изображения из документов.** DOCX (`word/media` + `r:embed`), PPTX
   (`ppt/media` + слайд), ODT (`Pictures/` + `draw:image`) отдают
   `DocumentImage` с подписью («Рис. N …»), соседним абзацем/заголовком и
   номером страницы/слайда; мусор (файл < 4 КБ, сторона < 64 px, повторы по
   SHA-256, не-JPEG/PNG) отбрасывается. Изображения раздела попадают только в
   фрагмент своего раздела; в запрос уходит блок `<images>` в формате
   `id | файл | подпись | окружающий текст` (бинарные данные — только как
   Vision-части, как раньше). Приоритет 1 — `image_id`, приоритет 2 — внешний
   поиск по `image_query`; производный запрос из текста вопроса удалён.
   В предпросмотре картинку можно убрать или заменить своим JPG/PNG.
   PDF-изображения внутри страницы не извлекаются — известное ограничение
   (PDF-сканы по-прежнему передаются страницами PNG для Vision).
4. **Д1. Prompt-only.** Пустые блоки пишутся одной строкой
   (`<materials></materials>`, `<images></images>`), блок `<wishes>` всегда
   присутствует; без файлов и темы кнопка «Сгенерировать» неактивна с
   подсказкой ARB; имя колоды по умолчанию — первые слова темы
   (`deckNameFromWishes`); `source_excerpt` при пустых материалах обнуляется
   без пометки, карточка остаётся.
5. **Лимит карточек из пожеланий.** Если в пожеланиях указано общее число
   («20 карточек»), приложение распределяет его по фрагментам пропорционально
   объёму (`distributeCardLimits`, сумма = запрошенному, ≤ 20 на фрагмент);
   иначе действует лимит фрагмента.
6. **Д5. Мягкие проверки качества** (пометки, не удаление): ответ/формула из
   back во front (`answerInFront`), front без вопроса и не cloze
   (`frontLooksLikeHeading`), back > ~200 символов/3 предложений
   (`backTooVerbose`), back — только список обозначений (`backOnlyNotation`),
   `image_query` для абстрактного понятия (`abstractImageQuery`), Unicode-
   математика и Markdown (`unicodeMath`, `markdownInText`). Eval-набор — три
   фикстуры-сценария в `test/unit/api/generation/quality_eval_test.dart`;
   live-тест считает долю помеченных карточек.
7. **Промпт `gen-ru-v5`** хранится дословно в `lib/api/prompts/system_prompt.dart`
   (raw-литерал) и `docs/prompts/gen-ru-v5.txt`; тест сверяет байты.

## Последствия

- Схема БД не меняется; `generation_jobs.prompt_version = gen-ru-v5`.
- Удалён `derivedImageQuery` (и его тесты) — поведение заменено правилом
  «нет `image_query` модели — нет внешнего поиска»; тесты `wishesForbidImages`
  сохранены.
- Ошибки фрагментов больше не выглядят как «неожиданный ответ»: причина
  различима по коду и в журнале, и в UI.
- Изображения из документов требуют JPEG/PNG; SVG/EMF/WMF в DOCX/PPTX и
  изображения внутри PDF — известное ограничение (см. `KNOWN_LIMITATIONS.md`).
- Ручная проверка в GUI (клики) остаётся за владельцем; живые вызовы модели и
  `integration_test` на десктопе покрывают путь генерации.
