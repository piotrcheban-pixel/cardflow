# ADR-003 — Форматы `.doc` и `.xls`: известное ограничение

**Дата:** 2026-11-11 · **Статус:** принято (итерация 0) · **Связано:** SPEC A8.3, B3.3, `docs/dependencies.md`, `journal/iteration-0/dependency-spike.md` §6

## Контекст

SPEC A8.3 требует нативного парсинга документов без WebView. Для современных форматов путь есть: DOCX/PPTX/ODT/XLSX — контейнер ZIP + XML (`archive` + `xml`), PDF — `pdfrx` (текстовый слой), TXT/MD — чтение файла с определением кодировки, RTF — собственный минимальный конвертер. Для старых бинарных форматов Microsoft Office `.doc` и `.xls` (OLE2/CFB container + BIFF/Word binary streams) SPEC сразу оговаривает, что зрелого Dart-пакета нет, и предписывает поведение по умолчанию:

> «Для `.doc`/`.xls` по умолчанию: “Формат не поддерживается. Сохраните файл как DOCX или XLSX и попробуйте снова”. Свой CFB-парсер — отдельной задачей по решению владельца, с обновлением ADR.»

Проверка на pub.dev 2026-11-11 (`journal/iteration-0/dependency-spike.md` §6):

- **`.doc`**: парсера legacy Word (CFB/OLE2 + Word binary) на pub.dev нет. Единственный CFB-пакет — [`cfb` 0.0.1](https://pub.dev/packages/cfb) (2020-08-01, `sdk: >=2.7.0 <3.0.0`, 1 like, license unknown, README-заглушка) — мёртв и несовместим с Dart 3.13. Остальное в выдаче — коммерческие SDK и просмотрщики.
- **`.xls`**: существуют два кандидата, читающих BIFF8: [`excel2003` 1.0.0](https://pub.dev/packages/excel2003) (2026-03-06, MIT по LICENSE-файлу, pure Dart, только чтение `.xls`, 2 likes, без publisher) и [`excel_plus` 2.29.2](https://pub.dev/packages/excel_plus) (2026-11-01, MIT, publisher `almasum.dev`, 72 likes, 160 pts; `Excel.decodeBytes` читает и `.xlsx`, и `.xls`). Ни один не проверялся на реальных фикстурах; зрелость/покрытие BIFF8 не подтверждены.
- **`.docx`/`.xlsx`** читаются штатно (DOCX — `archive`+`xml`; XLSX — `excel_plus` как замена устаревшего `excel`, см. `docs/dependencies.md`).

## Варианты

1. **Оставить известное ограничение** (вариант по умолчанию SPEC): `.doc`/`.xls` не принимаются, пользователь видит русское сообщение с подсказкой конвертировать формат. Нулевая стоимость, нулевой риск, соответствует SPEC.
2. **Свой CFB-парсер + разбор Word binary / BIFF** — по SPEC это **отдельная задача и решение владельца**. Объём: CFB-контейнер (FAT/miniFAT/DIFAT), далее два независимых бинарных формата; тестовые фикстуры. Для MVP неприемлемо.
3. **Подключить `excel_plus` / `excel2003` для `.xls`** — дешёвая попытка расширить поддержку, но библиотеки молодые/без подтверждённого покрытия BIFF8; SPEC A8.3 прямо не требует `.xls` в MVP (критерий B3.3: «работают все форматы A8.3 **или** ограничение по ADR-003»).
4. Коммерческие SDK — платно, только владелец; вне MVP.

## Решение

Принимаем **вариант 1** для MVP:

1. `.doc` и `.xls` **не поддерживаются**; такие файлы не передаются в парсер и не блокируют остальные файлы (ошибка по файлу, A8.3).
2. Пользователю показывается **точное сообщение из ARB** (ключ заводится в `lib/l10n/app_ru.arb`):
   > **Формат не поддерживается. Сохраните файл как DOCX или XLSX и попробуйте снова**
3. Расширение файла определяется по имени/сигнатуре; для `.doc`/`.xls` — сразу это сообщение, без попытки чтения.
4. Ограничение фиксируется в `journal/KNOWN_LIMITATIONS.md` (L7) и в отчёте итерации.
5. **Разрешённый спайк для будущей итерации (не блокирует MVP):** проверить `excel_plus 2.29.2` на наборе `.xls`-фикстур (значения, даты, несколько листов, кэшированные формулы). Если спайк успешен — обновить ADR-003 (перевод `.xls` в поддерживаемые) отдельным решением; `.doc` остаётся ограничением до отдельной задачи/решения владельца.
6. Guard/тест: unit-тест «.doc/.xls → сообщение из ARB, остальные файлы обрабатываются»; тот же тест защищает от случайного включения неподтверждённого парсера.

## Последствия

**Плюсы:** MVP не блокируется; поведение соответствует SPEC; нет риска падений/зависаний на бинарных форматах; пользователь получает понятную инструкцию; отсутствие платных зависимостей.

**Минусы:** часть реальных учебных материалов в `.doc`/`.xls` не принимается — требуется конвертация пользователем; в отчёте и `KNOWN_LIMITATIONS.md` это будет «частично/не проверено» по критериям, но допустимо по B3.3.

**Обязательства:** сообщение — только из ARB (guard `ru_strings_test.dart`); ошибка одного файла не блокирует остальные (A8.3); при появлении зрелого Dart-пакета или успешном спайке `excel_plus` — новый ADR, а не тихое изменение поведения.
