# ADR-021 — Ответ OpenAI-совместимых серверов: `max_tokens`, лестница совместимости, пустой `cards`

**Дата:** 2026-11-14 · **Итерация:** 7.6 · **Статус:** принято

## Контекст

Владелец сообщил: экран настроек API и сохранение ключей работают, но при генерации карточек
появляется ошибка «Нейросеть вернула пустой ответ».

Диагностика (живой DeepSeek + drift-БД приложения + разбор приложенных PDF) дала:

1. **Ответ модели не пустой и не битый.** Живой `deepseek-chat` возвращает `finish_reason = "stop"`
   и валидный JSON; для `deepseek-chat` — в markdown-ограждении ```` ```json … ``` ````, для
   `deepseek-reasoner` — чистым JSON. Tolerant-путь `CardGenerationService` это уже снимал.
2. **`response_format: json_schema` DeepSeek отклоняет** HTTP 400 `This response_format type is
   unavailable now`. Работал fallback без схемы (ADR-013), но каждый фрагмент тратил пробный запрос.
3. **`max_tokens` не передавался вообще**: `CardGenerationService.maxOutputTokens = 8192` до
   провайдера не доходил (`hasMaxTokens=false` в диагностике), поэтому действовал серверный дефолт
   DeepSeek — 4096 токенов на ответ (до 20 карточек + ограждение — впритык).
4. **`generation_jobs` владельца:** 5 записей, все `status=done`, `error_code=NULL`,
   `cards_count=0`. То есть модель **корректно** вернула `{"cards":[]}`: приложенные PDF — пустые
   бланки-формы (858 символов суммарно, из них почти всё — шапки таблиц и номера столбцов;
   правило 13 промпта: «Если материала нет — верни пустой массив cards»).
5. **Дефект UI:** `generation_screen.dart` показывал на этот успешный пустой результат строку
   `generationErrorEmptyResponse` — «Нейросеть вернула пустой ответ. Попробуйте ещё раз». Повтор не
   мог помочь, а текст указывал не на ту причину (материалы без фактов, а не пустой ответ модели).

## Решение

1. **`max_tokens` для OpenAI-совместимого протокола.** Адаптер передаёт `max_tokens =
   maxOutputTokens` (по умолчанию 8192). Нативные адаптеры не меняются: Anthropic/Gemini передают
   лимит по своему контракту, OpenAI — нет (поле устарело у части моделей).
2. **Лестница совместимости** (только `openai-completions`, только по `badRequest`):
   1. strict `response_format` + `max_tokens`;
   2. без `response_format` + `max_tokens` (DeepSeek и серверы без `json_schema`);
   3. без `response_format` + без `max_tokens` (серверы, требующие `max_completion_tokens`).
   Больше трёх запросов не бывает; ответ на любом шаге проходит локальную проверку A8.4 без
   послаблений. Параметр `sendMaxTokens` добавлен в контракт `GenerationProviderAdapter.buildRequest`.
   Для остальных протоколов поведение прежнее: `badRequest` отдаётся пользователю сразу.
3. **Разбор текста ответа вынесен** в чистый `CardsJsonExtractor`
   (`lib/api/generation/cards_json_extractor.dart`): снимает BOM, markdown-ограждение (```` ```json
   … ``` ````, ```` ``` ````, регистр языка), пояснительный текст до/после JSON; tolerant-режим —
   только для OpenAI-совместимого протокола (как и раньше).
4. **Пустой `cards` — не ошибка ответа.** UI показывает новую строку ARB `generationNoCardsFound`
   («Модель не нашла в материалах фактов для карточек. Проверьте, что в файлах есть текст (не скан и
   не пустая форма); если текст есть — смените модель»). Строка SPEC A6.8
   `generationErrorEmptyResponse` остаётся за кодом `emptyResponse` (провайдер вернул пустой
   `content`) и не переиспользуется.

## Варианты, которые не выбраны

- **Не передавать `response_format` в OpenAI-совместимом протоколе вообще.** Проще для DeepSeek, но
  лишает strict-схему серверы, которые её поддерживают (vLLM, Ollama, OpenRouter), и меняет ADR-013.
- **Кэшировать «сервер без `json_schema`» в памяти сервиса.** Экономит один 400 на фрагмент, но
  добавляет состояние в чистый сервис; вынесено в ограничение L50, а не в этой итерации.
- **Считать пустой `cards` ошибкой `emptyResponse`.** Неверно: модель отработала по правилу 13;
  подмена кода скрыла бы реальную причину (материалы без фактов).

## Последствия

- DeepSeek: первый запрос каждого фрагмента получает 400 (лишний round-trip, L50), второй — с
  `max_tokens=8192` — успешен (живой прогон 2026-11-14: `strict=400, tolerant=200, max_tokens=8192`).
- Риск обрезания длинного ответа серверным дефолтом 4096 снят для поддерживающих `max_tokens`.
- Серверы, требующие `max_completion_tokens`, работают через третий шаг лестницы (покрыто
  unit-тестами; живых серверов этого класса в окружении нет — L1/L47).
- Пользователь видит причину «материалы без фактов» вместо ложного «пустой ответ»; в `generation_jobs`
  по-прежнему `done` + `cards_count=0` (валидный пустой результат).
- Схема БД, `format_version`, публичные контракты экспорта не менялись.
