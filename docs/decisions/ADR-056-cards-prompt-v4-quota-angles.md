# ADR-056 — промпт `gen-cards-v4`: жёсткая квота и разные углы вместо обрезки

**Статус:** принято (2026-11-28, срез 18 генерации v3 — финальный срез темы).
**Контекст:** слепая выборка среза 17B показала паритет путей по качеству
(годных карточек v3 76,7 %, legacy 80,0 %), но владелец назвал отдельный дефект
поведения: при небольшом материале v3 отдаёт меньше карточек, чем заказано
(«30 запросил — получил 23»), потому что модель обрезает количество вместо
того, чтобы задать о том же факте другой вопрос. ADR-053/054/055 замораживали
формулировку `gen-cards-v3` и отправляли работу над дублями в S18. Срез 18 —
этот S18: тема генерации закрывается, новых промптов после v4 не будет.

## Решение

1. **`gen-cards-v4` — дефолтная версия этапа Generation.** Текст — константа
   `cardsSystemPromptGenCardsV4` в `lib/api/prompts/cards_prompt.dart`,
   дословная копия — `docs/prompts/gen-cards-v4.txt` (байтовая сверка тестом).
   `cardsPromptVersion = 'gen-cards-v4'`, `cardsSystemPrompt` указывает на v4;
   порт `AdapterCardsBatchPort` берёт дефолтный промпт, а не константу версии.
   `gen-cards-v3` **не удалён**: константа, копия и байтовая сверка остаются.
2. **Жёсткая квота внутри партии.** Правило 1: «Ты ОБЯЗАН сгенерировать ровно
   <budget cards> карточек. Это строгая квота. По одной на каждую строку
   <card>, не больше и не меньше». Квота — это бюджет **партии** из
   `AllocationPlan`; модель не вправе отдать меньше строк бюджета.
3. **Нехватка фактов не обрезает количество, а меняет угол.** Правило 2: если
   уникальных фактов меньше, чем `<budget cards>`, модель обязана использовать
   разные углы (angles) одного факта — определение, применение, cloze; правило 3
   запрещает две карточки с одинаковым `front`, правило 4 требует для
   `card_type 'cloze'` разметку `{{c1::пропуск}}` (иначе `'basic'`). Это
   переносит борьбу с дублями с «молчаливой обрезки» на «другой вопрос».
4. **Схема ответа, план, валидатор и пороги не меняются.** v4 — только текст
   промпта: `cardsResponseSchemaV3`, `AllocationPlan`, `CardValidator`,
   `Dedup` и метрики ADR-054 остаются прежними. Версия v4 попадает в
   `generation_jobs.prompt_version` и `GenerationReport.promptVersions` через
   существующий `cardsPromptVersion`.
5. **Маскировка cloze в слепой выборке — в домене, а не в скрипте.** L240
   (сырая разметка `{{c1::…}}` в файле выборки) закрывается функцией
   `clozeQuestionText` (`lib/domain/cards/cloze_markup.dart`): пропуск
   показывается как `[…]`. Скрипт `tool/blind_sample_s17b.dart` использует её
   вместо приватной копии, поведение покрыто unit-тестами.

## Границы (что этим ADR не обещано)

- **«Ровно N» ограничено планом.** Промпт гарантирует, что модель отдаст все
  карточки бюджета партии и не обрежет их из-за нехватки фактов. Сам бюджет
  строит `AllocationPlan`: у единицы не больше четырёх различимых слотов
  (`unit_id + angle`), а «ёмкость по богатству» (ADR-053 §3) может быть меньше
  четырёх. Поэтому заказ, который больше различимой ёмкости материала, честно
  остаётся `materialLimited` — приложение показывает «материала примерно на N
  карточек», а не выдумывает факты. Срез 18 аллокацию не меняет: её правка —
  отдельное продуктовое решение с перемером, а TASK части 1 говорит только о
  промпте.
- **v4 не измерен живым прогоном.** TASK части 3 требует только analyze,
  format, тесты, CI и релизный билд; потолка на живой замер не выделено.
  Сравнивать v4 с v3 по `dupRate`/доле годных в этом срезе нельзя — это была бы
  догадка, а не число (ADR-054 §1). Следующая живая проверка — при следующем
  продуктовом замере.
- **Путь по умолчанию не меняется.** `auto` по-прежнему = legacy
  (`kGenerationPathV3MinUnits = null`): v4 — промпт пути v3, а не основание
  включать v3 по умолчанию.

## Последствия

- Промптверсия по умолчанию в журнале/отчётах — `gen-cards-v4`; старые записи
  `gen-cards-v3` читаются как есть (поле строковое).
- v3 остаётся воспроизводимым: его текст и копия не тронуты, поэтому прежние
  замеры (`live-s12`…`live-s17b`) остаются сопоставимыми с той версией, которой
  они получены.
- Тесты: `cards_prompt_test` (v4 — квота/углы/cloze/дефолт + байтовая сверка,
  v3 — сохранён и совпадает), `cards_batch_port_test` (запрос дефолтным
  промптом, `promptVersion` = v4), `request_ledger_test` (v4 в задании),
  `generation_v3_path_wiring_test` (production-проводка), `cloze_markup_test`
  (+4, L240).
