# ADR-052 — флаг `generationPipelineV3`, вердикт завершения и границы среза 9

**Статус:** принято (2026-11-28, срез 9 генерации v3). **Контекст:** `TASK.txt`
«Срез 9» требует включить новый путь флагом, показать этапы/приёмочные числа,
показать «Почему?» по якорям, снять метрики и **не** включать флаг по умолчанию.

## Решение

1. **Флаг живёт в `AppSettings`** (`generationPipelineV3`, JSON
   `generation_pipeline_v3`, по умолчанию `false`, ADR-019 §1). Значение читается
   `generationRunnerProvider` → `GenerationPipeline(pipelineV3:)`; переключатель —
   на экране «Провайдеры». Пересборка не требуется.
2. **Путь v3 на этом срезе — слой завершения.** Флаг включает:
   - вердикт по журналу (`CompletionVerdict`): `done` ⟺ `принято ≥ заказано`,
     иначе `partial` с числом и машинной причиной; `generation_jobs.status`
     берётся из вердикта (ложный успех запрещён, ARCH §3.2);
   - дедупликацию-пометку: почти-дубль **остаётся** (`possibleDuplicate`),
     точный отбрасывается (ARCH §3.4);
   - «Почему?» по якорям: `SourceAnchorResolver` даёт **блок** `ContentModel`,
     а не склеенную цитату;
   - метрики прогона (`GenerationMetrics`) в результате и debug-диагностике;
   - UI: степпер этапов, итог и причины недобора, группировка по темам, пометки.
3. **Этапы v3 не переводятся на production-исполнение этим срезом.** Причина:
   у `UnderstandingService` нет HTTP-вызова (`KnowledgeMapCaller` — только
   контракт, S3), а у плана v3 — моста от `GenerationPlan` к `AllocationPlan`.
   Флаг, который «включал» бы несуществующую проводку, был бы мёртвой заглушкой
   (AGENTS: «функция либо работает, либо её нет»). Границы прямо описаны в
   `journal/iteration-8/summary.md` §4 и Q19.
4. **Старый путь не удаляется** (протокол §9): флаг выключен по умолчанию, старый
   путь — production. Удаление legacy — отдельным срезом после default-on и
   отчёта, каждое удаление — со ссылкой на защищающий тест (Q21).

## Последствия

- Оба пути проходят тесты; при выключенном флаге поведение прежнее (регрессионные
  тесты среза 9: `generation_pipeline_v3_flag_test`, сценарии
  `generation_paths_compare_test`).
- Схема БД не менялась (`schemaVersion = 2`), `format_version` — тоже.
- `GenerationRunResult.verdict/metrics/possibleDuplicates` — аддитивные поля с
  умолчаниями: старые результаты/тесты не ломаются.
- Метрики p50/p95 в отчёте измерены на фейковых вызовах; живые прогоны — известное
  ограничение (L1/live-тесты).
