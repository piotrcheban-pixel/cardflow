# ADR-032 — Режимы «Тест» и «Ввод ответа»: общий контроллер, политика FSRS и сравнение ответов

**Дата:** 2026-11-16 · **Итерация:** 7.15 · **Статус:** принято

## Контекст

Владелец: режимов (Классика, Лента, Тренировка) мало; нужно лучшее из Quizlet
(Test, Write), Anki (typing/matching) и Knowt/Brainscape. Требования:

- общие `StudyMode` и контроллер сессии, чтобы новые режимы не дублировали
  очередь/прогресс/итоги;
- **расписание FSRS не искажается:** due-карточки оцениваются в FSRS, карточки
  с `due` в будущем проходятся как Тренировка (без записи в FSRS), в
  `review_logs` добавляется `mode`;
- `AnswerType.classify(card)`, `AnswerMatcher`, `DistractorGenerator` — чистый
  домен с тестами, включая UI-диффы;
- схема БД не меняется без отдельного решения.

Ограничения: локаль только `ru`; никаких мёртвых кнопок; покрытие ≥ 80 %;
`schemaVersion = 1` не трогаем.

## Решение

### 1. Домен

- `lib/domain/study/study_mode.dart` — enum `StudyMode` с `wireName`
  (`test`, `typing`, `match`, `true_false`), `canWriteFsrs`, `writesReviewLog`.
- `study_fsrs_policy.dart` — `isDueForStudy`: новая карточка (`state = new`)
  тоже «due» (первая оценка создаёт расписание, как в Классике); карточка с
  `due` в будущем — тренировка. `shouldWriteFsrs` учитывает поддержку режима.
- `study_queue.dart` — очередь: due и новые (порядок `ReviewQueue`), затем
  будущие `due`; `suspended`/buried исключены.
- `answer_type.dart` — `short_text | number | formula | long_text`; пригодны для
  ввода только короткий текст и число (≤ 60 символов, ≤ 6 слов, без LaTeX и
  переносов).
- `answer_normalization.dart` — Unicode NFC (`unorm_dart`), нижний регистр,
  `ё`→`е`, сжатые пробелы, пунктуация по краям, несколько ответов через
  `/`/`;`, число `3,5 = 3.5`.
- `answer_matcher.dart` — `exact | almost | wrong`, Левенштейн ≤ 1 для ответов
  до 6 символов и ≤ 2 для длинных, посимвольный diff (missing/extra) для UI.
- `distractor_generator.dart` — три неверных ответа из той же колоды и того же
  типа, близких по длине (числа — та же единица и правдоподобная размерность),
  без дублей правильного; позиция правильного — `Random(seed ^ card.id)`;
  принимает `aiDistractors` для колод с малым числом ответов; при нехватке
  возвращает `null` (карточка пропускается).

### 2. Общий контроллер (UI-слой)

`lib/ui/study/study_session_controller.dart`: очередь `StudySessionItem`
(карточка + снимок `SchedulingCard` + флаг `writesFsrs`), индекс, busy,
correct/wrong, undo, `repeatMistakes()`. Для due-карточек — `Scheduler.review` +
`ReviewRepository.recordReview(mode: mode.wireName)`; для остальных —
`PracticeRepository.recordPractice(mode: mode.wireName)` (порт расширен
необязательным `mode`; undo удаляет лог по id). Счётчики и итоги живут в
контроллере, экраны только рендерят.

### 3. Экраны

- `MultipleChoiceScreen`: вопрос + 4 варианта; правильный — зелёный, выбранный
  неверный — красный и правильный зелёный; верный ответ авто-переходит через
  1,2 с (кроме reduce motion), иначе «Далее»; пружинная анимация нажатия и
  haptics (по настройке); клавиши 1–4 и Enter; итоги (точность, ошибки,
  «Повторить ошибки»).
- `TypingScreen`: поле с автофокусом, Enter отправляет; exact → Good, almost →
  Hard + жёлтая плашка «Почти!» и diff, wrong → Again + красная плашка и diff;
  «Я был прав» (undo + повторная запись Good), «Показать ответ» → Again.
  Карточки без пригодного ответа в режим не попадают; пустое состояние
  объясняет причину.
- Лист режимов: «Тест» и «Ввод ответа» с иконкой, описанием в одну строку и
  числом доступных карточек; без подходящих карточек пункт неактивен с
  подсказкой. Маршруты `/decks/:deckId/{test,typing}`; строки — ARB (ru).

## Последствия

- + Единая политика FSRS и журнал `mode` для всех новых режимов.
- + Домен сравнения/дистракторов покрыт unit-тестами; экраны — widget-тестами.
- − ИИ-дистракторы (batch на колоду) реализованы только как вход
  `aiDistractors` генератора: production-источника ИИ и кэша в БД/настройках
  пока нет. Колоды, где меньше 4 подходящих ответов, не получают Тест для этих
  карточек (ограничение L87).
- − `review_logs.mode` не имеет CHECK-ограничения (схема v1): новое значение
  `true_false`/`typing`/`test`/`match` валидно без миграции.
- − `unorm_dart` — новая зависимость (чистый Dart, MIT), проверена pub.dev
  (`0.3.3`, опубликована 2026-10-04) и записана в `docs/dependencies.md`.
