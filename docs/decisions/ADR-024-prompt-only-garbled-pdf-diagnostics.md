# ADR-024 — Генерация по теме без файлов, стойкость PDF-текста и диагностика ответов

**Дата:** 2026-11-15 · **Итерация:** 7.10 · **Статус:** принято

## Контекст

Владелец проверил генерацию 7.9 и сообщил три критических бага:

1. без прикреплённых файлов карточки не генерируются, хотя достаточно описать тему;
2. PDF приводит к сообщению «Модель вернула неожиданный ответ»;
3. Word разбирается без ошибки, но картинки в карточках не появляются.

Спайк этой итерации показал фактические данные:

- PDFium (pdfrx) возвращает из PDF **C1-управляющие** `U+0080–U+009F`
  (`buildPdf('\u0080\u0081\u0082')` → `codeUnits [128,129,130]`), а битый ToUnicode-словарь
  даёт `U+FFFD` или **одиночные суррогаты** (`[65533,…]`, `[55296,…]`). `TextSanitizer`
  удалял только ASCII-управляющие (`\u0000–\u001F`, `\u007F`), поэтому такой текст уходил
  в JSON запроса и провайдер отвечал 400 или мусором вместо JSON.
- схема `gen-ru-v3` содержит `image_query`, но правило 14 факультативно, поэтому модель
  отдаёт `null`; проводка `ImageSearchService` существует, но проверена только через фейк.

Ограничения: схема БД и `format_version` не меняются; ключи не логируются; SPEC A8.1 —
промпт скрыт в коде, стандартный формат ответа A8.4 не меняется.

## Варианты

### Генерация без файлов

| Вариант | Оценка |
|---|---|
| **A. Отдельный «тематический» режим и отдельный промпт** | второй промпт и второй путь валидации, расхождение качества; лишний код |
| **B. Один путь: пустой `<materials>` + тема в `<wishes>` (выбрано)** | тот же пайплайн, та же схема A8.4 и `generation_jobs`; правило промпта объясняет модели, что делать |
| **C. Подставлять тему в `<materials>`** | тема — пожелание пользователя, а не материал-источник; ломает `source_excerpt`-семантику и правило «внутри materials — только данные» |

### PDF-текст

| Вариант | Оценка |
|---|---|
| **A. Оставлять как есть, ошибку показывать «неожиданный ответ»** | диагностика бесполезна, баг не исправлен |
| **B. Санитизация Unicode + проверка UTF-8 и порог U+FFFD → `garbledText` (выбрано)** | чистая функция, покрывается unit-тестами и фикстурой Type0/ToUnicode; пользователь видит понятную строку |
| **C. Свой PDF-парсер/DjVu-OCR** | вне MVP, тяжёлые зависимости |

### Диагностика

| Вариант | Оценка |
|---|---|
| **A. Полное логирование тел запросов/ответов** | нарушает запрет AGENTS и раскрывает материалы/ответы модели |
| **B. Debug-only диагностика: тело ошибки провайдера + сырой ответ модели, редакция секретов, лимит длины (выбрано)** | даёт данные для owner-note «выведи сырой ответ», в release молчит; тела по-прежнему не попадают в UI и не логируются целиком в production |
| **C. Ничего не логировать** | баг 2 и 3 нечем диагностировать |

## Решение

1. **Prompt-only.** `GenerationScreen` не требует файлов: запуск разрешён, если есть
   пожелания (тема/описание) и выбран настроенный провайдер. `GenerationPipeline`, если
   чанкер не дал фрагментов, а `wishes` не пусты, создаёт один фрагмент с `materialsText: ''`;
   `buildGenerationUserContent` допускает пустой `<materials>`; `CardGenerationService`
   бросает `noMaterials` только когда нет ни текста, ни вложений, ни пожеланий.
   Промпт `gen-ru-v4` (правила 8, 12, 13, 14): пустой `<materials>` означает «тема в
   `<wishes>`», карточки строятся по общим знаниям, `source_excerpt` — `null`.
2. **PDF.** `TextSanitizer` — единственная точка санитизации текста: удаляет Unicode
   категории Cc/Cf (кроме `\t`, `\n`), одиночные суррогаты (невалидный UTF-16/UTF-8),
   `U+2028/U+2029` → `\n`, BOM. `PdfTextQuality` (api/parsers) проверяет исходный текст:
   нормализация UTF-8 (одиночные суррогаты → `U+FFFD`) и доля замен: **≥ 5 замен и ≥ 5 %**
   → `ParserErrorCode.garbledText` → ARB «PDF содержит нечитаемый текст». Порог проверен
   программными фикстурами PDF (Type0/Identity-H + ToUnicode).
3. **Диагностика.** `GenerationDiagnostics` (`lib/api/generation/`) — чистый Dart,
   `enabled = !const bool.fromEnvironment('dart.vm.product')`, sink инжектируется.
   `GenerationHttpClient` пишет статус + редактированное тело ошибки, `CardGenerationService` —
   сырой ответ модели (для проверки `image_query`). Редакция: секреты (`sk-…`, `AIza…`,
   `Bearer …`), управляющие символы, лимит 2000 символов; сообщения не попадают в UI/БД/ARB.
   В релизной сборке методы — no-op. Для 400 UI по-прежнему показывает безопасную причину
   провайдера (`providerReason`, ADR-022) сквозь пайплайн до предпросмотра.
4. **Картинки.** Промпт v4: для `basic`/`cloze`, если карточка описывает объект, животное
   или понятие, `image_query` обязателен (английский); запрет картинок в `<wishes>` в силе.
   Проводка проверяется интеграционным тестом на production-графе с реальным
   `ImageSearchService` (Openverse через fake-Dio): `image_query` → скачивание → `GeneratedCard.image`
   → `MediaStore` + `media` при импорте.

## Последствия

- `generation_jobs.prompt_version` для новых заданий — `gen-ru-v4`; старые записи сохраняют `gen-ru-v3`.
- `noMaterials` теперь означает «совсем нет входа» (нет текста, вложений и пожеланий), а не
  «нет файлов»; UI-строка `generationNoFilesError` заменяется проверкой темы.
- Диагностика включается только в debug/профиле и только в консоль (не в UI); тела запросов
  в лог по-прежнему не попадают никогда (только ответ и только при ошибке/разборе).
- Новых зависимостей и изменений схемы БД нет.
