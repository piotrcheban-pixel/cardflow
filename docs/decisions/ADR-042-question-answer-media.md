# ADR-042 — Независимые изображения вопроса и ответа (`media_json` v2, `gen-ru-v9`)

**Дата:** 2026-11-21 · **Итерация:** 7.19 «Изображения: диагностика и стороны» ·
**Статус:** принято.
Связано: SPEC A5/A6.3/A6.8/A8.4; ADR-009/017/028/031/041; аудит
`journal/iteration-7.19/audit.md` §5–§7.

## Контекст

До 7.19 карточка хранила один плоский список `cards.media_json` (`["id"]`), а
`CardContentView` брал `card.mediaIds.first` **независимо от стороны** и рисовал
его и до, и после переворота. Схема ответа модели содержала одно поле
`image_id` — модель не могла выразить «это изображение относится к ответу».

Следствие на фактической карточке владельца (сценарий B): вопрос «Какой
формулой рассчитывают фактическую воздухопроницаемость окна?», медиа —
PNG из PDF с той же формулой и её расшифровкой (`provider=file`), и это
изображение показывалось на **лицевой** стороне: ответ раскрывался картинкой
до переворота.

## Решение

### 1. Сторона в данных: `media_json` v2, без миграции БД

`cards.media_json` получает версию 2:

```json
{"version": 2, "question": ["id…"], "answer": ["id…"]}
```

- старый массив `["id…"]` читается как сторона **вопроса** (до 7.19
  единственная иллюстрация показывалась на лицевой стороне);
- кодировщик всегда пишет v2; `schemaVersion` БД не меняется;
- `CardMediaSides` (`lib/domain/cards/card_media_json.dart`) — единственный
  разбор/кодировщик; битый JSON — `FormatException`, а не «нет изображений»;
- домен: `Card.questionMediaIds` / `answerMediaIds`, `mediaIds` — производное
  объединение для GC, экспорта и загрузки медиа.

### 2. Сторона в ответе модели: `gen-ru-v9`

```json
{
  "front": "…", "back": "…", "card_type": "basic",
  "tags": ["…"], "hint": null, "source_excerpt": null, "source_file": null,
  "section_id": null,
  "question_image_ids": ["img3"],
  "answer_image_ids": ["img7"],
  "image": {"query": "…", "fallback_query": "…", "kind": "diagram",
            "side": "question"}
}
```

- `question_image_ids` — стимул вопроса; `answer_image_ids` — то, что содержит
  или раскрывает ответ; массивы обязательны и могут быть пустыми;
- один id в обеих коллекциях запрещён: остаётся у вопроса, из ответа
  удаляется, пометка `imageDuplicatedSide`;
- id вне каталога фрагмента отбрасывается (`imageIdUnknown`), карточка не
  теряется;
- `image` — необязательный объект внешнего поиска **настоящей** фотографии;
  `side = question | answer | none`. Поиск выполняется только для выбранной
  стороны и только если у неё нет изображений из `<images>`; неудача —
  `imageNotFound`, без подмены (ADR-041);
- совместимость v5–v8: `image_id` → сторона вопроса, `image_query` → поиск для
  вопроса, отсутствие `side` → вопрос. Локальная терпимая схема
  (`localCardItemSchema`) принимает обе формы, строгая канон-схема — только v9.

Системный промпт: `gen-ru-v8` сохранён дословно
(`docs/prompts/gen-ru-v8.txt`), новый блок `gen-ru-v9` дописан к нему; версия
`systemPromptVersion = 'gen-ru-v9'`, копия — `docs/prompts/gen-ru-v9.txt`
(тест сверяет байты).

### 3. Отображение и редактор

- `CardContentView`: до переворота — только `questionMediaIds`, после — только
  `answerMediaIds`; occlusion-иллюстрация — общий холст (маски управляются
  раскрытием, иначе переворот терял бы маски);
- поддерживается несколько изображений на каждой стороне;
- редактор карточки — два независимых списка: добавление, удаление, замена,
  порядок, перенос на другую сторону; сохранение — через `CardDraft`
  (`questionMediaIds`/`answerMediaIds`, `questionUploads`/`answerUploads`);
- `basic_reversed`: у парной строки стороны меняются местами (её вопрос —
  исходный ответ);
- предпросмотр генерации показывает обе стороны отдельно — ровно то, что
  увидит пользователь на экране обучения.

### 4. Экспорт/импорт

`cards.json` архива получает необязательные `question_media_ids` /
`answer_media_ids`; старые архивы без них читаются как «всё на стороне
вопроса». При импорте id переназначаются с сохранением сторон; стороны обязаны
покрывать `media` без повторов (`invalidCards` иначе).

## Последствия

- Сторона изображения — часть контракта данных и ответа модели, а не UI-флаг.
- Изображение, раскрывающее ответ, физически не попадает на лицевую сторону.
- `MediaGarbageCollector` и `DriftDeckTransferService` используют
  `CardMediaSides`; битые данные не приводят к удалению возможных медиа.
- Миграции БД нет: всё расширение — JSON существующей колонки.
