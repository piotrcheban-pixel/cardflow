# ADR-028 — Картинки на всех типах карточек, дневной лимит и поиск иллюстраций

**Дата:** 2026-11-15 · **Итерация:** 7.12 · **Статус:** принято

## Контекст

Owner-note после 7.11: (1) новый пак карточек сразу блокируется «Дневной лимит
исчерпан»; (2) добавление картинки принудительно включает Image Occlusion;
(3) ИИ не добавляет картинки в сгенерированные карточки.

Диагностика по фактическим данным приложения (`cardflow.sqlite`):

- `daily_new_limit = 20`, за 2026-11-15 выполнено **30** «новых» оценок
  (`review_logs.mode IN (classic, feed)`, `actual_days IS NULL`) — лимит дня
  израсходован ещё до создания нового пака; в 21:08 создана колода и в 21:11
  сгенерировано 13 карточек, сессия по ним пуста.
- Задание `2b2d5c61…` (`deepseek-flash`, `gen-ru-v4`, PDF о минералах) дало
  13 карточек, у всех `media_json = []`.
- Живой зонд сырого ответа (диагностика ADR-024): `deepseek-flash` на
  определениях возвращает `image_query: null` (4 запроса из 12 на тексте о
  минералах); Wikimedia Commons на «спайность минерала», «плотность минерала»,
  «генезис минерала» отдаёт 0 файлов (поиск по именам файлов не понимает
  словоформы), Openverse таймаутит по 8 с, из-за чего бюджет 45 с выгорал.
- DuckDuckGo Image API отвечает `botnet_challenge` (HTTP 202), Pexels/Pixabay
  требуют API-ключ, которого в окружении нет.
- Форма карточки (`card_form_screen.dart`) показывала изображение только для
  `basic` и при выборе картинки сразу создавала `OcclusionDocument()` →
  сохранение без масок падало `occlusionMasksMissing`. Домен и drift-репозиторий
  уже принимали `mediaIds` любого типа — ограничение было только в UI.

## Решение

### 1. Медиа — для любого типа карточки (ADR-028 §1)

- В форме карточки секция «Изображение» доступна `basic`, `basic_reversed`,
  `cloze`: выбрать/заменить/удалить картинку.
- Маски Image Occlusion — **необязательный** переключатель, только для `basic`,
  по умолчанию выключен. Включён → прежняя валидация: изображение + ≥ 1 маска.
  Выключен → `occlusion_json = null`, карточка получает обычную иллюстрацию.
- Старая occlusion-карточка открывается с включёнными масками; выключение масок
  сохраняет изображение.
- Домен: `mediaIds` документированно применим к любому типу; добавлены
  `CardDraft.primaryMediaId`, `CardDraft.hasImage`, `Card.primaryMediaId`.
  Схема БД и `occlusion_json` не менялись.

### 2. Дневной лимит и новые карточки (ADR-028 §2)

- `ReviewQueue.build`: новые карточки, созданные **в текущий локальный
  календарный день**, входят в очередь всегда, независимо от остатка лимита
  новых. Лимит новых продолжает ограничивать вчерашние и более ранние
  невыученные карточки; лимит повторных и порядок ADR-008 не меняются.
  Границы дня — `DailyLimits.localDayUtc` (тот же расчёт, что расход дня).
- Дополнительно: при пустой очереди из-за лимита экран колоды показывает
  предупреждение «Дневной лимит исчерпан» с кнопками **«Продолжить без лимита»**
  (маршрут `/decks/:id/study?limits=ignore` и `/feed?limits=ignore`),
  «Тренировка» и «Отмена». Экран сессии в пустом состоянии предлагает те же
  действия; «Продолжить» перестраивает очередь без лимитов.
- Отключение лимитов — явное действие пользователя после предупреждения, а не
  тихое игнорирование: FSRS-расписание всё равно обновляется, поэтому лимит
  остаётся продуктовым ориентиром, а не жёстким запретом.

### 3. Поиск иллюстраций (ADR-028 §3)

- Источники: **Wikimedia Commons** (конкретные запросы) → **Wikipedia
  pageimages** (`ru`, затем `en`: поиск статьи, а не файла, — понимает русские
  словоформы) → **Openverse** (CC-резерв, таймаут 5 с).
- Если модель не вернула `image_query`, для предметных `basic`-вопросов запрос
  выводится локально (`derivedImageQuery`: «Что такое X?», «X — это …» и т. п.;
  до 8 слов/80 символов). При пожеланиях, запрещающих картинки
  (`wishesForbidImages`), не ищется ничего — ни модельный, ни производный запрос.
- Неудачный поиск не проглатывается: карточка получает
  `CardIssueCode.imageNotFound`, предпросмотр показывает предупреждение
  «Не удалось найти картинку по запросу: N» и пометку карточки. Скачанная
  картинка отображается в предпросмотре и импортируется в `media`.
- Debug-диагностика `GenerationDiagnostics` в приложении пишет в консоль
  `flutter run` (`debugPrint`), поэтому сырой ответ модели (`image_query`) и
  итог каждого источника видны при разборе; release — no-op, тела не логируются.
- Бюджет суммарного времени поиска увеличен с 45 до 90 с: цепочка из трёх
  источников на неудачных запросах дольше, и прежний бюджет обрезал карточки,
  которые ещё можно было найти.
- Отклонены: DuckDuckGo Image API (bot-challenge), Pexels/Pixabay (нужен ключ,
  которого нет в окружении). Wikimedia не «заменена», а дополнена Wikipedia:
  сетевой сбой Wikimediа-инфраструктуры по-прежнему оставляет карточки без
  картинок, но UI больше не молчит.

## Последствия

- Пользователь, создавший/импортировавший карточки сегодня, всегда может их
  пройти; лимит новых действует начиная со следующего дня.
- Картинку можно прикрепить к любой карточке; occlusion — осознанный выбор.
- DeepSeek-flash с пустым `image_query` для определений всё равно получает
  иллюстрацию из Wikipedia/Commons, если статья/файл найден; иначе пользователь
  видит предупреждение в предпросмотре.
- Схема БД, `schemaVersion`, `format_version` и форматы экспорта не менялись.

## Ограничения

- Живой поиск зависит от сети: при блокировке Wikimedia-доменов картинок не
  будет (предупреждение в UI остаётся).
- Производный запрос покрывает только определения (`basic`); сложные вопросы и
  cloze по-прежнему зависят от `image_query` модели.
- Релевантность превью Wikipedia не оценивается (может быть иллюстрацией
  смежной статьи); это плата за работу без ключа и без ручного выбора.
