# ADR-017 — Разметка Cloze/LaTeX и медиа Image Occlusion

**Дата:** 2026-11-14 · **Итерация:** 5 · **Статус:** принято
**Контекст SPEC:** A0.1/A0.2, A5, A6.3, A7.2/A7.3, A7.8–A7.10, A8.4; ADR-006/009/016.

## Контекст

SPEC задаёт поведение трёх видов содержимого, но не определяет JSON масок, привязку нового изображения
к карточке до получения `cards.id`, группировку одинаковых номеров cloze и представление шагов LaTeX.
При этом публичный формат архива и схема БД уже содержат `media_json`, `occlusion_json`, `latex`;
менять их версию не требуется и без решения владельца нельзя менять экспортный контракт.

## Варианты

1. Хранить в `occlusion_json` абсолютные пути и пиксели. Отклонено: пути не переносятся между ОС,
   маски ломаются при масштабировании, экспорт раскрывает локальную структуру каталогов.
2. Создать отдельные типы сессий/экраны для occlusion/cloze/LaTeX. Отклонено: прямо запрещено A0.1,
   дублирует классику/ленту и ломает общие оценки.
3. Типизированная доменная разметка + существующие `media_json`/`occlusion_json`, единый интерактивный
   контент внутри обеих сессий. **Принято.**

## Решение

### 1. Image Occlusion и медиа

- `occlusion_json` — JSON-объект `{"version":1,"masks":[…]}`. Маска:
  `{"id":"…","shape":"rectangle|ellipse","x":0.0,"y":0.0,"width":0.2,"height":0.1}`.
  Координаты — доли ширины/высоты исходного изображения; `x,y ≥ 0`, `width,height > 0`,
  `x+width ≤ 1`, `y+height ≤ 1`, id уникален. Некорректный JSON не проходит ручную валидацию;
  импортированная битая разметка не роняет сессию, а показывает текст и предупреждение.
- Изображение одно на occlusion-карточку: его id — первый элемент существующего `media_json`.
  Дублировать id внутри `occlusion_json` не нужно. Путь остаётся относительным `media/<uuid>.<ext>`.
- Выбранные в форме байты входят в `CardDraft` как отдельный upload. `DriftCardRepository` создаёт
  `cards.id`, затем атомарно записывает файл и строки `media`/`cards` в одной логической операции;
  при ошибке удаляет новый файл и откатывает БД. Схема и `format_version` не меняются.
- Поддерживаются PNG/JPEG через существующий `file_picker`, лимит 25 МБ. В сессию байты попадают
  через `CardMediaRepository`, UI не читает drift напрямую.
- Удаление/замена очищает неиспользуемые медиа. Conservative GC удаляет только файлы в `media/`,
  отсутствующие в строках `media`, и строки, не связанные ни с одной картой; остальные файлы не трогает.

### 2. Cloze

- Синтаксис — `{{cN::ответ}}`, N — положительное целое. Одинаковые N образуют одну группу и
  раскрываются вместе; группы раскрываются тапом по очереди в порядке первого появления.
- Общее раскрытие классики/ленты показывает все группы и `back`; скрытие карточки возвращает маски.
  Состояние раскрытия ephemeral, не пишется в БД и не влияет на FSRS.
- Ручная форма предлагает тип `cloze`; пустой `back` разрешён, но хотя бы один корректный пропуск
  обязателен. Тип при редактировании остаётся неизменяемым (ADR-009).

### 3. LaTeX

- Источник формул — inline-разметка в `front`/`back`; необязательное поле `latex` добавляется к ответу,
  если оно уже пришло импортом. Поддерживаются только `$…$` и `$$…$$`, как в A7.10.
- Несколько формул на стороне — шаги: сначала видна первая, тап «Следующий шаг» открывает следующую;
  общее раскрытие показывает все. Это локальное UI-состояние, не отдельные review events.
- Если хотя бы одна формула не парсится `flutter_math_fork`, сторона целиком остаётся текстом и
  показывает ARB-предупреждение «Ошибка разметки формулы». Сырые parse errors не попадают в UI.
- Проверка генерации остаётся в `lib/api/generation/latex_checker.dart`; нативный рендер — в UI-слое,
  без WebView и HTML.

### 4. Общий контент и жесты

- `CardContentView` используется классикой и лентой. Обычный текст сохраняет прежний `Text` и ключи,
  чтобы контракт прежних тестов не менялся без продуктовой причины.
- Тап по cloze/маске/шагу обрабатывает дочерний жест и не ставит оценку; общий тап карточки, Space,
  рейтинг и undo остаются в движках ADR-008/016.
- Occlusion показывается на обеих сторонах; общее раскрытие также раскрывает все маски. Кнопки
  «Показать все»/«Скрыть все» доступны независимо от общей стороны.

## Последствия

- Экспорт/импорт автоматически переносит новые данные существующим ADR-006-кодеком; нужен сквозной
  тест create → export → import → session, а не только unit-тесты слоёв.
- Ручной `CardDraft` расширяется optional-полями, поэтому прежние вызовы generation/import совместимы.
- Появляются файловые side effects в card repository; они требуют тестов отката и очистки.
- Реальные системный picker, точность рисования пальцем и screen reader на устройстве остаются
  ручной приёмкой; widget/unit/integration-тесты компенсируют это до ручного прогона.
