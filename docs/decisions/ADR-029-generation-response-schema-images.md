# ADR-029 — Схема ответа модели `gen-ru-v5`: поля `image_id` и `image_query`

**Дата:** 2026-11-15 · **Итерация:** fix-gen · **Статус:** принято

## Контекст

Владелец проверил генерацию вручную и нашёл, что иллюстрации из прикреплённых
файлов не используются (Д3), а внешние картинки часто не относятся к вопросу
(Д2: «шар» для аксиомы статики, биология для аксиомы связей). Живые данные
`cardflow.sqlite`: задания `gen-ru-v4` давали `media_json = []`; у части заданий
— `invalidResponse` и `truncated` (см. `journal/iteration-fix-gen/diagnosis.md`).

Причина по картинкам: схема A8.4 знала только `image_query` (внешний поиск) и
не имела способа сослаться на изображение из приложенного документа. Модель,
даже увидев рисунок в DOCX/PPTX, не могла сказать «возьми его».

Новая версия промпта `gen-ru-v5` (дословная копия —
`docs/prompts/gen-ru-v5.txt`) требует два поля:

- `image_id` — id изображения из каталога `<images>` прикреплённых файлов;
- `image_query` — короткий запрос внешнего поиска на английском.

## Решение

1. **Каноническая схема** (`lib/api/generation/card_json_schema.dart`) получает
   свойство `image_id` типа `["string","null"]`; список `required` теперь девять
   ключей: `front`, `back`, `hint`, `tags`, `card_type`, `source_excerpt`,
   `source_file`, `image_id`, `image_query`. `additionalProperties: false`
   сохраняется — строгий режим OpenAI.
2. **Проекции провайдеров не меняются по форме**: OpenAI получает канон как
   есть, Gemini — `nullable: true`, Anthropic — `anyOf` с `null`
   (`provider_schema.dart`). Добавление поля автоматически попадает во все три
   проекции, тесты проекций и `propertyOrdering` обновлены.
3. **Локальный валидатор** (`card_content_validator.dart`):
   - `image_id` вне каталога `<images>` фрагмента → `null` + пометка
     `CardIssueCode.imageIdUnknown` (карточка остаётся);
   - если `image_id` задан, `image_query` игнорируется;
   - `image_query` не на латинице, длиннее 7 слов или длиннее 200 символов →
     `null` + `imageQueryAdjusted`;
   - `image_query` для абстрактного понятия (аксиома, закон, теорема, формула,
     определение, свойство, принцип, классификация, правило, термин, алгоритм)
     → `null` + `abstractImageQuery` (Д2: лучше без картинки, чем с
     неподходящей);
   - `tags` обрезаются до 3, без `#` и пустых (как раньше).
4. **Пайплайн** разрешает `image_id` в байты изображения из каталога фрагмента
   и только затем ищет внешнюю картинку по `image_query` (если `image_id`
   нет). Производный запрос из текста вопроса **удалён** — это был источник
   неподходящих картинок (Д2).
5. **БД не меняется.** `image_id`/`image_query` — wire-поля ответа модели:
   `image_id` живёт в памяти до импорта, выбранные байты пишутся в
   `MediaStore` + `media` (существующая колонка `media_json`), как и
   найденные внешние картинки. Новая колонка не требуется — решение владельца
   о схеме БД не запрашивается.

## Последствия

- `gen-ru-v5` пишется в `generation_jobs.prompt_version`; старые задания
  остаются с `gen-ru-v4` — регрессии качества можно связать с версией промпта.
- Провайдеры со strict-схемой получают обязательное `image_id` в каждом
  объекте; тестовая JSON-фикстура карточки обновлена в одном месте
  (`test/helpers`/`card_schema_test.dart` и интеграционные фикстуры).
- Промпт-тест сверяет константу `systemPromptGenRuV5` с
  `docs/prompts/gen-ru-v5.txt` байт в байт — случайное редактирование копии
  ловится тестом.
- Формулы: `JSON-экранирование` модели больше не роняет фрагмент (см.
  ADR-030, Д4/Д6).
