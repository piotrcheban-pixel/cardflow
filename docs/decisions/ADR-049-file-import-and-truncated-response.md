# ADR-049 — Импорт файлов: PDFium вне `HOME`, поддерживаемые форматы и оборванный ответ модели

**Дата:** 2026-11-27 · **Итерация:** TASK 04 «Импорт файлов, генерация,
изображения и производительность» · **Связано:** SPEC A8.3, A8.5; ADR-003,
ADR-010, ADR-021, ADR-024, ADR-027, ADR-040, ADR-043, ADR-048

## Контекст

Тестирование на реальном Android-смартфоне выявило набор дефектов импорта и
генерации:

1. **PDF на Android** («обычный», с текстовым слоем) давал «Не удалось
   прочитать файл». На Windows/CI тот же файл разбирался. Причина измерена по
   исходникам зависимостей: `PdfParser` (и рендер/извлечение изображений)
   вызывает `pdfrxInitialize()` **без** `tmpPath`. В `pdfrx_engine 0.9.1`
   (`pdfrx_initialize_dart.dart`) на не-Windows платформах каталог кэша
   вычисляется как `Directory(path.join(Platform.environment['HOME']!, ...))`.
   В процессе Android-приложения переменная `HOME` не задана → разыменование
   `null` падало **до** открытия документа, и `ParserException(unreadableFile)`
   показывал общую строку. Ветка Windows берёт `LOCALAPPDATA`, поэтому дефект
   не воспроизводился ни локально, ни в CI.
2. **Форматы.** Пикер отдавал только список из `DocumentFormat.values` без
   `.ppt`; `.doc`/`.xls` отвечали общим «формат не поддерживается», хотя
   пользователю нужен конкретный следующий шаг. На Android
   `FileType.custom` + `allowedExtensions` превращается в MIME-список
   (`MimeTypeMap`), у `.md`/`.rtf` MIME может отсутствовать — плагин пишет
   предупреждение и **не показывает** файл в диалоге.
3. **`content://`.** Проверено по исходникам `android_file_picker 2.1.5`
   (`FileUtils.openFileStream`): выбранный файл копируется в кэш приложения и
   `PlatformFile.path` указывает на эту копию; `content://` остаётся только в
   `identifier`. То есть «pdfrx не умеет `content://`» само по себе PDF не
   ломало — но приложение не имело ни временной копии URI для платформ без
   пути, ни отдельного кода ошибки доступа.
4. **«Запрошено 50, получено 32».** Когда модель упирается в лимит вывода
   (`finish_reason: length`, Gemini `MAX_TOKENS`, Anthropic `max_tokens`),
   адаптер бросал `GenerationException(truncated)` **до** разбора тела. Уже
   полученные карточки фрагмента выбрасывались целиком; восстановление дробило
   лимит заново, а пользователь видел недобор без причины («ограничение
   контекста» нигде не объяснялось).
5. **Изображения.** Поиск иллюстраций уже был best effort внутри партии, но
   исключение при разрешении картинок могло выбраться из цикла партии и
   оборвать запуск; причины недобора (обрыв, сбой, исчерпание) не попадали в
   UI числами.
6. **Лента.** `FeedCardView` передавал `imageMaxHeight = max(96, min(160,
   h·0,24))`, классика — `max(140, h·0,42)`: на телефоне фото в ленте было в
   2–3 раза меньше.
7. **Анимации.** `AnimatedBuilder` перестраивал всё содержимое карточки каждый
   кадр переворота (включая `CardContentView` и разбор заголовка изображения),
   `BoxShadow` пересчитывался на каждом кадре, `Image.memory` декодировал
   оригинал 4K в память ради слота ~300 px.

## Решение

### 1. PDFium инициализируется только с явным каталогом

- `lib/api/parsers/pdfium_bootstrap.dart` — единственная точка инициализации:
  `Pdfrx.cacheDirectoryPath = path` + `pdfrxInitialize(tmpPath: path)`. Каталог
  по умолчанию — `Directory.systemTemp/cardflow-pdf`, **никогда** не `HOME`.
- `PdfParser`, `PdfScanRenderer`, `PdfImageExtractor` принимают
  `cacheDirectory` и получают его копией (`withCacheDirectory`).
- `FileParsingService` разрешает каталог в **main-изоляте**
  (`path_provider.getTemporaryDirectory`) до `Isolate.run`: вызовы
  платформенных каналов из фонового изолята невозможны, а строка безопасно
  передаётся в изолят. Провайдер — `fileParsingServiceProvider`.
- Guard `test/guards/pdfium_android_cache_test.dart` запрещает прямой
  `pdfrxInitialize()` вне bootstrap-файла и требует `tmpPath`.

### 2. Форматы и сообщения

- `DocumentFormat.ppt` добавлен; `.doc`/`.ppt`/`.xls` — `isSupportedForParsing =
  false`. Для `.doc`/`.ppt` — **отдельные** коды
  `ParserErrorCode.docFormatNotSupported`/`pptFormatNotSupported` и строки
  «Сохраните файл как .docx/.pptx». Собственный CFB-парсер не пишем
  (ADR-003): в Dart нет надёжной библиотеки Compound File Binary, а
  недоделанный парсер рискует тихо терять содержимое.
- Пикер: на Android/iOS — `FileType.any` (фильтр по MIME теряет `.md`/`.rtf`),
  расширение проверяет парсинг и даёт строку ARB; на десктопе — прежний
  `FileType.custom`.
- `content://` и любой не-`file` URI читаются в байты и **материализуются** во
  временный файл приложения (`getTemporaryDirectory/cardflow-import`), копия
  удаляется после разбора (`DocumentGateway.releaseDocument`). Нечитаемый URI
  даёт `ParserErrorCode.fileAccessDenied`, а не общее «не удалось прочитать»;
  ошибка одного файла не отменяет остальные.

### 3. Обрыв ответа не теряет карточки

- `ProviderRawResponse.truncated`: адаптеры (OpenAI, OpenAI-compatible, Gemini,
  Anthropic) возвращают тело с флагом вместо исключения; исключение остаётся
  только когда спасать нечего.
- `CardsJsonExtractor.salvageCards` собирает **полностью закрытые** объекты
  `cards` из прерванного JSON; незавершённая карточка отбрасывается, остальные
  проходят схему A8.4 и контентные правила обычным путём.
- `GenerationResult.truncated/salvagedCards`, `GenerationRunResult.
  truncatedChunks/salvagedCards/imageResolveFailures`; пайплайн считает их,
  недостача уходит в раунды добора (`top-up`) до заказа, а
  `GenerationDiagnostics.runSummary` пишет числа «запрошено/создано/упало/
  оборвано/спасено/сбоев картинок/исчерпано разделов».
- UI: если создано меньше заказа, до предпросмотра показывается диалог
  «Создано меньше, чем запрошено» с причиной (обрыв по лимиту контекста,
  исчерпанный материал, иное) и кнопками «Продолжить»/«Отмена»; предпросмотр
  отдельной строкой сообщает об обрывах и спасённых карточках.

### 4. Изображения — best effort

Разрешение картинок карточки обёрнуто в защищённый участок: исключение
сохраняет карточку **без** изображения (с пометкой `imageNotFound`), партия и
запуск продолжаются; число сбоев видно в диагностике и результате.

### 5. Единый бюджет изображения

`CardImageBudget.side` (`lib/ui/cards/content/card_image_view.dart`) — одна
формула для «Классики», «Ленты» и «Тренировки»: доля доступной высоты (42 %,
минимум 140/160), ширина колонки до 560, «рядом с текстом» — 36 % колонки (до
420) и полная высота. Раскладка «рядом» включается по одному правилу
`cardWidth >= 760`.

### 6. Анимации без перестройки содержимого

- `SessionCard`/`FeedCardView`: сторона выбирается **один раз** на середине
  переворота (listener контроллера + `_showBack`), `AnimatedBuilder` двигает
  только `Transform` над готовым `RepaintBoundary(child: face)`; тень
  (`BoxShadow`) рисуется только в покое (`_animating`);
- `CardImageView`: `RepaintBoundary` вокруг изображения и `cacheWidth` по слоту
  и DPR (не более 4096 px, без апскейла), поэтому 4K-файл не декодируется
  целиком;
- `_FeedFace` планирует проверку переполнения не чаще одного раза на кадр.

## Последствия

- На Android PDF, `.docx/.pptx/.txt/.md/.rtf/.xlsx/.odt` читаются через
  локальную копию; ошибки различаются кодами (пароль, повреждение, скан,
  доступ, размер, старый формат).
- `.doc`/`.ppt` не поддерживаются осознанно (ADR-003): пользователь получает
  инструкцию пересохранить файл.
- Обрыв ответа модели больше не уменьшает результат молча: карточки
  сохраняются, недостача добирается, недобор объясняется числами и требует
  подтверждения.
- PDFium инициализируется с каталогом из `path_provider`; в фоновом изоляте
  используется переданная строка (никаких переменных окружения).
- Схема БД, `schemaVersion`, `format_version` и FSRS-логика не менялись.

## Альтернативы

- **Свой CFB-парсер `.doc`/`.ppt`** — отклонён: недели работы, риск тихой
  потери содержимого; просьба пересохранить файл честнее.
- **Вызов `pdfrxFlutterInitialize()` в `main()`** — не решает задачу: статика
  `Pdfrx.cacheDirectoryPath` у каждого изолята своя, а `pdfrxInitialize()` всё
  равно вычисляет `HOME` до проверки `??=`. Поэтому каталог передаётся явно.
- **Хранить обрезанный ответ как ошибку фрагмента** — отклонено: теряются
  оплаченные карточки, а «повторить неудавшиеся» повторно платит за тот же
  текст.
- **Собственный `cacheWidth` для всех картинок без учёта DPR** — отклонено:
  на Retina/3x изображение выглядело бы размытым.
