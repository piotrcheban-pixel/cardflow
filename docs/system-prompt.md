# Системный промпт генерации CardFlow

**Версия:** `gen-ru-v9` (итерация 7.19/фикс генерации; ADR-042; предыдущие
`gen-ru-v5`…`v8` сохранены в коде и в `docs/prompts/`) · **Связано:** SPEC A8.1,
A8.4, A8.5; ADR-011, ADR-029, ADR-030, ADR-031, ADR-037, ADR-040, ADR-042
**Источник правды в коде:** `lib/api/prompts/system_prompt.dart`
(`systemPromptGenRuV9`, `systemPromptVersion = 'gen-ru-v9'`).
**Дословная копия текста:** `docs/prompts/gen-ru-v9.txt` (тест сверяет
константу и файл байт в байт).

## 0.00 Что нового в `gen-ru-v9` (ADR-042)

`gen-ru-v9` = `gen-ru-v8` дословно + блок «ИЗОБРАЖЕНИЯ: СТОРОНЫ ВОПРОСА И
ОТВЕТА»:

- `question_image_ids` — изображения стимула вопроса, `answer_image_ids` — то,
  что содержит или раскрывает ответ; оба массива обязательны, могут быть пусты;
- `image` — необязательный объект внешнего поиска настоящей фотографии;
  `side` выбирает сторону (`question`/`answer`/`none`), поиск — только если у
  стороны нет изображений из `<images>`;
- один и тот же `image_id` не может быть на обеих сторонах; без подходящей
  картинки карточка остаётся с пустыми массивами (синтетических заглушек нет,
  ADR-041).

**Production-фикс (итерация «Диагностика и фикс пайплайна генерации»):**
`CardGenerationService`, `GenerationPlanBuilder`, `GenerationRequestEstimator`
и нативный `count_tokens` в пайплайне по умолчанию шлют **`gen-ru-v9`**.
До этого они оставались на `gen-ru-v8`, хотя `generation_jobs.prompt_version`
и схема ответа уже были v9: модель не получала контракт сторон и возвращала
только legacy-поля v5–v8.

## 0.0 Что нового в `gen-ru-v8` (ADR-040)

`gen-ru-v8` = `gen-ru-v7` дословно + блок «ПЛАНИРОВАНИЕ ВЫДАЧИ»: хвост `<task>`
(`<part>`, `<focus>`, `<cards>`, `<context_only>`, `<already_created>`),
`section_id` у карточки и `source_exhausted` в корне ответа. Неизменный
префикс сообщения — `<materials>`, `<images>`, `<outline>`, `<wishes>`;
между запросами одного запуска различается только `<task>` (кэш префикса).

## 0. Что нового в `gen-ru-v7` (ADR-037)

`gen-ru-v7` = `gen-ru-v6` дословно + блок «ИЗОБРАЖЕНИЯ ИЗ PDF И СКАНОВ»:

- модель обязана анализировать изображения вместе с текстом и использовать
  `image_id`, если изображение существенно для вопроса/ответа;
- нельзя игнорировать изображения, если в них есть учебная информация,
  отсутствующая в текстовом слое;
- нельзя строить карточки только по тексту, если важная информация — на схеме,
  графике или изображении;
- как читать каталог PDF/скана: `стр. N` в строке каталога, подпись каталога
  перед каждой image-частью (модель сопоставляет картинку с `image_id`),
  приоритет полной страницы/её области, поведение при усечении по лимиту.

Промпт `gen-ru-v6` остаётся константой (`systemPromptGenRuV6`) и файлом
`docs/prompts/gen-ru-v6.txt`; тесты v5/v6 продолжают сверять байты.

## 1. Правила

- Промпт хранится в коде как константа-сырой литерал (`r'''…'''`), в UI **не
  показывается и не редактируется** (A8.1). Обратные слэши в примерах LaTeX
  сохраняются только в raw-строке.
- Версия пишется в `generation_jobs.prompt_version`, чтобы связать регрессию
  качества карточек с изменением промпта.
- Промпт одинаков для всех фрагментов одного запуска (кэшируется провайдером):
  пожелания пользователя — отдельный блок `<wishes>`.
- `gen-ru-v5` заменяет `gen-ru-v4` целиком (не дополнение): роль
  «эксперт-методист по интервальному повторению», блоки `<materials>`,
  `<wishes>`, `<limit>`, `<images>`, логика prompt-only, правила атомарности,
  «front не содержит ответа», краткости back, LaTeX/Markdown, типы карточек,
  теги/подсказка/источник, изображения (`image_id`, `image_query`), формат
  JSON и самопроверка перед ответом.
- Пользовательское сообщение собирается **строго** из блоков:
  `<materials>`, `<wishes>`, `<limit>`, `<images>` (`buildGenerationUserContent`).
  Пустые блоки пишутся одной строкой: `<materials></materials>`,
  `<images></images>`. Каждый файл в `<materials>` начинается со строки
  `Файл: <имя>`; каталог `<images>` — по строке
  `id | файл | подпись | окружающий текст`; для изображений из PDF/скана
  «окружающий текст» начинается со страницы (`стр. N`, `стр. N, область скана`).
- `<limit>` — максимум карточек в ответе. Если в пожеланиях указано общее
  число карточек, приложение распределяет его по фрагментам пропорционально
  объёму (`lib/domain/generation/generation_card_limit.dart`), иначе действует
  лимит фрагмента (`kMaxCardsPerChunk = 20`).

## 2. Текст `gen-ru-v5`

Полный текст — в `docs/prompts/gen-ru-v5.txt`; в коде — та же строка в
`lib/api/prompts/system_prompt.dart`. Тест `test/unit/api/generation/prompt_test.dart`
сверяет:

- версию `gen-ru-v5`;
- совпадение константы с файлом **байт в байт**;
- наличие ключевых правил (блоки, «Файл: <имя>», LaTeX-экранирование,
  запрет картинок для абстрактных понятий, `image_id`/`image_query`,
  самопроверка).

## 3. Почему промпт сменился (fix-gen)

- **Д2:** прежние правила подталкивали модель искать картинку для любого
  понятия; появились «шар» для аксиомы статики и биология для аксиомы связей.
  `gen-ru-v5` запрещает `image_query` для абстрактных понятий и вводит
  приоритет изображения из файла (`image_id`).
- **Д4/Д6:** промпт прямо требует удваивать обратные слэши LaTeX в JSON;
  приложение дополнительно восстанавливает одиночные слэши (защита от ошибок
  модели), но промпт остаётся первым рубежом.
- **Д1:** prompt-only описан явно: пустой `materials` → `wishes` — тема,
  генерация по проверенным общим знаниям; количество — по `<limit>`.
- **Д5:** правило «front не содержит ответа» усилено примерами (формула
  момента силы, аксиома о равновесии двух сил, формула фермы, да/нет), а
  самопроверка требует перечитать каждую карточку.
