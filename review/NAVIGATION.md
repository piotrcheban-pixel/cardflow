# Карта навигации и выходов — CardFlow 1.0.0 (снимок `53ead19`)

Аудит только по проверенным на живом Windows-приложении экранам; где проверка невозможна — явно помечено «не проверено» с причиной. Маршруты — из `lib/ui/router/app_router.dart`.

**Соглашение:** «главное меню» = экран «Мои колоды» (`/`, стартовый экран и единственный раздел, откуда доступны все остальные). «Действие» = одно нажатие/одна клавиша.

---

## 1. Общая схема

```
StatefulShellRoute (AppShell: боковая панель 240 px + шапка 56 px, при ширине < 1024 px — Drawer)
├── ветка 0  /            → Мои колоды (DecksScreen)
├── ветка 1  /statistics  → Статистика (StatisticsScreen)
└── ветка 2  /settings    → Настройки (SettingsScreen)
        └── /settings/generation → Провайдеры и ключи (GenerationSettingsScreen)
                └── Лицензии (push, без именованного маршрута)

Поверх оболочки (полноэкранные маршруты, панель приложения отсутствует):
├── /decks/:deckId                 → Колода (DeckScreen)
│   ├── /decks/:deckId/study       → Классическая сессия (ReviewSessionScreen)
│   ├── /decks/:deckId/feed        → Лента (FeedSessionScreen)
│   ├── /decks/:deckId/practice    → Тренировка (PracticeSessionScreen)
│   ├── /decks/:deckId/test        → Тест (MultipleChoiceScreen)
│   ├── /decks/:deckId/typing      → Ввод ответа (TypingScreen)
│   ├── /decks/:deckId/match       → Подбор пар (MatchScreen)
│   ├── /decks/:deckId/true-false  → Верно/Неверно (TrueFalseScreen)
│   ├── /decks/:deckId/generate    → Генерация в колоду (GenerationScreen)
│   ├── /decks/:deckId/cards/new   → Новая карточка (CardFormScreen)
│   └── /decks/:deckId/cards/:id/edit → Редактирование карточки (CardFormScreen)
├── /generate                      → Генерация (GenerationScreen)
├── /constructor                   → Конструктор сессии (SessionConstructorScreen)
├── /session/classic, /session/feed → сессия по плану конструктора (план в GoRouter.extra)
```

## 4. Что происходит при выходе (сохранение/потеря)

| Сценарий выхода | Данные | Проверено |
|---|---|---|
| Оценка карточки в сессии → «×» → «Выйти» | Оценки уже в БД (текст диалога это подтверждает); прогресс не теряется | да: после выхода колода показала 0 к повторению, «Изучено» увеличилось (`deck_04_after_session_exit.png`) |
| Сессия → «×» → Esc (в диалоге) | Остаётся в сессии, оценки целы | да (`study_02c_dialog_closed_esc.png`) |
| Форма карточки → «←» после правок | **Правки теряются молча** | да (`cardform_04_unsaved_discarded.png`) |
| Форма карточки → закрытие окна ОС | Не проверено (риск тот же, `PopScope` нет) | нет |
| Настройки → смена темы/масштаба | Применяется сразу, без «Сохранить» и без «Отменить» | да (тема сменилась мгновенно) |
| Генерация → «←» во время работы | По коду `PopScope(canPop: !_generating)` — выход блокируется | **не проверено** (генерацию не запускал) |
| Импорт → «Отмена» в системном диалоге | Ничего не меняется, реакции нет | да (`import_02_cancelled.png`) |

## 5. Тупики и экраны без выхода

1. **`/generate` — «односторонний» экран (blocker).** Постоянной шапки нет; единственная стрелка «назад» находится в прокручиваемом содержимом (`generation_screen.dart:886-908, 1403`). После прокрутки к разделу «3. МОДЕЛЬ И ПАРАМЕТРЫ» на экране не остаётся ни одного элемента выхода, `Esc` игнорируется. Пользователь вынужден прокручивать всю форму вверх или закрывать окно приложения.
2. **Пять режимов обучения — выход только через диалог.** «×» видим, но путь в главное меню — 3 действия; клавиатурного выхода (`Esc`) нет.
3. **«Тест» и «Подбор пар» недоступны** при малом числе карточек, причём «Тест» не сообщает, сколько карточек нужно и каких («Мало подходящих карточек»). Формально это не навигационный тупик, но путь к режиму отсутствует без объяснения.
4. **Сессия после завершения** всё ещё требует подтверждения выхода (лишний барьер, не тупик).
5. **Экран «Сессия по плану» без `extra`** (прямой переход) показывает «План сессии не найден» с кнопкой «Назад» — по коду тупика нет, но **в живом приложении не проверено** (маршрут недостижим без плана).

**Экранов, куда можно попасть и откуда нельзя вернуться совсем, — один: нижняя часть `/generate` при прокрутке (без использования прокрутки/закрытия приложения).**

## 6. Вложенность и «назад» ведёт не туда

* Переходы в подэкраны выполняются `context.push`, поэтому «назад» последовательно возвращает: сессия → колода → колоды; генерация → колоды; форма карточки → колода. **Накопления экранов не обнаружено** (проверено на цепочках колода → форма → назад; колода → сессия → выход → колода; колоды → генерация → назад).
* Исключение: сессия из конструктора возвращает в **конструктор**, а не в колоду (ожидаемо и корректно, т.к. это `push` из конструктора), но добавляет шаг до главного меню.
* Ветки оболочки (`StatefulShellRoute`) сохраняют состояние: переход «Колоды → Настройки → Колоды» возвращает на прежнюю позицию прокрутки — это плюс, но одновременно кнопка «Назад» внутри ветки недоступна (нет истории внутри ветки), а глобальная панель скрыта на подэкранах.

## 7. Вердикт по навигации: **НЕ УДОВЛЕТВОРЯЕТ**

* Из 16 проверенных экранов **1 — с реальной потерей выхода** (`/generate`), **5 — с 3 действиями до главного меню**, **2 — с потерей данных при выходе** (формы карточки).
* Диалоги и листы закрываются корректно (крестик/кнопка/фон/Esc) — здесь всё в порядке.
* Системная кнопка «назад» обрабатывается через `PopScope` во всех сессиях — но только на Android; на Windows `Esc` не работает ни на одном экране.
* Отдельно: диалог выхода делает опасное действие главным (N4), а после завершения сессии спрашивает подтверждение, хотя терять уже нечего (N7).

**Минимально необходимое для «норма»:** закреплённая шапка с «Назад» на `/generate`; `Esc` → назад на всех экранах; подтверждение несохранённых правок в форме карточки; путь из сессии в «Мои колоды» за ≤ 2 действия; приоритет безопасной кнопки в диалоге выхода.
