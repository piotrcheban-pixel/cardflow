## 2. Паттерны, на которые опирается решение

Ниже — паттерны, известные по продуктам класса (Anki/AnkiDroid, Quizlet,
RemNote, Duolingo, Mochi; Notion, Linear, Todoist, Things, Google Keep, Apple
Notes, Shorts-подобные ленты). Это **не цитаты и не пересказ конкретных
экранов** — это общеизвестные принципы, проверяемые на практике; каждый
адаптирован к CardFlow и подтверждён измерением/тестом.

### 2.1. Учебные приложения

| Паттерн | Как используется у лучших | Решение CardFlow |
|---|---|---|
| Карточка — главный объект | карточка занимает основную площадь, хром минимален | карточка ≥ 80 % рабочей высоты на телефоне; шапка 52–56 px, прогресс одной строкой |
| Переворот | тап по карточке; анимация 200–350 мс; не «две стороны одновременно» в свободном просмотре | классика: 3D-flip 300 мс (уже есть); лента: только ответ после переворота, повторный тап возвращает вопрос |
| Оценка после ответа | 3–4 равноправные кнопки, подписи действий; интервалы — вторичны | 2×2 на телефоне, 48 px, только название действия, интервал не печатается |
| Прогресс | тонкая полоса/сегменты, без дублирования счётчиков | одна строка: «1 / 12» + полоса; «Оценено» убрано на мобильной ширине |
| Свободный просмотр | отдельный режим, не меняет расписание | ADR-044: лента без FSRS; оформление и навигация отличаются от классики |
| Редактор | короткая форма, второстепенное — в «Дополнительно»/подсказку | поля + раскрываемые «Дополнительно»; пояснения за `?` |
| Длинный текст | читается целиком: скролл внутри карточки или отдельный лист | классика — скролл с градиентом; лента — лист «Открыть полностью» без наложения на текст |
| Изображения | превью + полноэкранный просмотр, без обрезки | `BoxFit.contain`, тап — fullscreen (уже есть), сетка 2 колонки |
| Тренировка/практика | явно помечена как «без влияния на расписание», но не текстом на пол-экрана | компактный чип «Без FSRS» с подсказкой |

### 2.2. Продуктивные приложения

| Паттерн | Решение CardFlow |
|---|---|
| Минимальный хром, заголовок + одно основное действие | шапки: назад, название, одно контекстное действие; лишние иконки — в меню/подсказку |
| Нижняя панель действия | `AppActionBar` с SafeArea, кнопка на всю ширину на телефоне, фиксированная высота, не перекрывает контент |
| Формы: секции, помощь по запросу | `AppSectionHeader(title, info)`; длинные абзацы не в постоянном потоке |
| Bottom sheet: «лист», а не «окно» | `DraggableScrollableSheet`, старт 0,72 высоты, максимум 0,92, свайп вниз закрывает даже из прокрутки |
| Контекстные меню вместо россыпи кнопок | плитка изображения: превью + «Заменить» (иконка) + ⋮; в меню — порядок/сторона/обновить/удалить |
| Пустые состояния с одним главным CTA | сохранены; второстепенные действия — текстовые, вторичный тон |
| Анимации только функциональные | одна шкала 120/200/220/280/300 мс, reduced motion, без пульсаций |

### 2.3. Чужие ошибки, которые не повторяем

- Не переносим на телефон десктопный `Row` «текст + кнопка» без мобильной
  ветки — это причина M-02 и прошлого дефекта Empty State.
- Не показываем интервалы/прогнозы на кнопках оценок (владелец уже отверг).
- Не делаем bottom sheet во всю высоту для меню — это ломает жест закрытия.
- Не оставляем вопрос и его изображения на обороте свободного просмотра.
- Не решаем длинный текст уменьшением кегля до нечитаемого.

## 3. Дизайн-система v4 (мобильная надстройка над ADR-045)

Палитра ADR-045 уже соответствует требованию владельца: кобальт `#1E4FD8`
на нейтральном графите, без фиолетового сдвига. **Палитру не переписываем** —
переписывание сломало бы guard контраста и целостность; вместо этого
фиксируем правила и добавляем мобильные токены. Фиолетовый фон, который видит
владелец, в текущих токенах отсутствует: поверхности `#F6F7F9` / `#FFFFFF`,
контейнеры `#F0F2F5` / `#E9EBEF` — нейтральные серые (проверяется тестом
`test/guards/contrast_test.dart` и снимком). Если на устройстве владельца
виден фиолетовый оттенок, это старая сборка либо Dynamic Color — в отчёте
указано, как проверить.

### 3.1. Цветовые роли (светлая тема)

| Роль | Токен | Значение | Применение |
|---|---|---|---|
| Фон приложения | `surface` | `#F6F7F9` | подложка экранов |
| Карточка | `surfaceContainerLowest` | `#FFFFFF` | карточка сессии, листы |
| Поверхность 2-го уровня | `surfaceContainerLow` | `#F0F2F5` | футер карточки, плашки |
| Поверхность 3-го уровня | `surfaceContainer` | `#E9EBEF` | чипы, трек прогресса |
| Текст | `onSurface` | `#14181F` | вопрос/ответ |
| Вторичный текст | `onSurfaceVariant` | `#4A5260` | подписи, echo |
| Границы | `outline` | `#6E7683` | контур интерактивных элементов |
| Разделители | `outlineVariant` | `#CDD2DA` | линии внутри карточки |
| Основное действие | `primary` | `#1E4FD8` | «Знаю», «Показать ответ» |
| Успех | `secondary` | `#0F6B5C` | «Легко», успешные состояния |
| Предупреждение | `tertiary` | `#8A5300` | предупреждения |
| Ошибка | `error` | `#B3261E` | «Не знаю», удаление |

Правила: на экране **одно** залитое primary-действие; цветные заливки — только
у оценки и статуса; градиенты и свечения запрещены.

### 3.2. Типографика на телефоне

Шкала ADR-038 остаётся; мобильные правила:

| Элемент | Размер/высота | Правило |
|---|---|---|
| Заголовок экрана | 22–24 / 1,25 | одна строка, ellipsis только для названия колоды |
| Вопрос карточки | 28 / 1,35 (на < 360 — 26) | по центру, максимум 6–8 строк, дальше — скролл |
| Ответ | 0,88 вопроса, ≥ 20 | не крупнее вопроса; выравнивание по левому краю при > 160 знаков |
| Повтор вопроса (классика) | 0,74 вопроса, ≥ 17 | только текст, 2–3 строки, без изображений |
| Подпись стороны | 13 / 1,3, uppercase, tracking 0,6 | primary для вопроса, secondary для ответа |
| Подпись кнопки оценки | 16, w600 | центр, без ellipsis |
| Служебный текст | 13–14,5 | только в подсказках/чипах, не постоянным абзацем |

Запрещено: кегль < 13; перенос слова внутри подписи; колонка текста уже 220 px;
`maxLines: 1 + ellipsis` для названий действий.

### 3.3. Отступы и размеры (мобильная ступень)

- Горизонтальные поля: 16 (`AppSpacing.md`); внутри карточки 20.
- Вертикальные интервалы: 4/8/12/16/20/24.
- Кнопки: 48 (основные), 44 (вторичные), цель ≥ 44.
- Поля ввода: высота 48, радиус 12.
- Радиусы: 12 контролы, 16 панели, 20 карточка/лист.
- Иконки: 20 (строки), 24 (действия).
- Шапка сессии: 52; прогресс: 20.

### 3.4. Компоненты

1. `ReviewToolbar` (переработан): сетка 2×2 / ряд 4, высота 48/56, `FittedBox`,
   без ellipsis; состояния pressed/hovered/focused/disabled.
2. `AppSectionHeader` (`lib/ui/components/app_section_header.dart`): заголовок +
   `?`-кнопка; по нажатию — лист с объяснением (не tooltip-only: на телефоне
   long-press неизвестен).
3. `AppActionBar`: SafeArea + клавиатура, кнопка на всю ширину на `< 600`.
4. `AppSheetFrame`: draggable bottom sheet, стандарт для длинных списков.
5. `AppImageTile` (редактор): превью 16:9, тап — fullscreen, «Заменить» +
   ⋮, компактная сетка.
6. `FeedCardView` (переработан): собственный flip, только ответ на обороте,
   футер без наложения, финал ленты.
7. `SessionCard`: компактный футер, echo без медиа, чистый прогресс.

### 4.4. Bottom sheet режимов

- старт: 72 % высоты экрана; максимум 92 %;
- drag handle + заголовок с ×;
- прокрутка содержимого и свайп вниз в одной системе
  (`DraggableScrollableSheet`);
- SafeArea снизу; на 320×640 заголовок и все группы достижимы;
- закрытие: свайп вниз, тап по фону, системный Back.

## 6. Критерий выбора решений

Решение принимается, если одновременно:
1. убирает измеренный дефект (а не «иначе выглядит»);
2. сохраняет функциональность и FSRS-инварианты;
3. проверяется тестом/снимком на 320–430 px и при кегле до 200 %;
4. не добавляет дублирующий компонент;
5. не ухудшает контраст (guard ≥ 4,5:1 текст / ≥ 3:1 границы).
