# Summary 7.19 — изображения: первопричина и независимые стороны

**Дата:** 2026-11-21 · **Итерация:** 7.19 · **Ветка:** `main` · **ADR:** 041, 042.
**Живых API-запросов нет** (запрет задания).

## 1. Точная первопричина повторяющейся картинки

Одинаковая абстрактная картинка с геометрическими фигурами и графиком — это
**не** исходное изображение, не общий fallback-asset и не ошибка сопоставления
image id. Это **нарисованная заглушка** `PlaceholderImageGenerator`, которую
`GenerationPipeline._placeholderOrNothing` создавал при **любой** неудаче
привязки изображения и сохранял как обычное медиа карточки:

- PNG 800×450/800×600: диагональный градиент, 2–3 круга, две полосы и иконка
  вида (`diagram` — оси и три столбика, т.е. «график»);
- палитра — `contentHash % 8`, поэтому разные карточки получали **разные байты**
  (уникальные SHA-256), но визуально почти одинаковую композицию;
- сохранялась в `media`, `MediaStore`, `<path>.meta.json`
  (`isPlaceholder: true`), попадала в `media_json`;
- `main.dart` при старте дополнительно запускал `retryPlaceholders()`.

Промпт `gen-ru-v8` требовал изображение **у каждой** карточки, что делало
подмену массовой. Фактическая БД владельца: **80 из 207** медиа — заглушки,
68 из них `kind=diagram`, 15 визуальных групп (крупнейшая — 16 карточек).
Это ситуация **B** из §0.2: разные исходные изображения потерялись, а
интерфейс показывал универсальную по композиции картинку (генерируемую
заново), а не один asset по общему id.

## 2. Какие участки кода её вызывали

| Участок | Роль |
|---|---|
| `lib/api/images/placeholder_image_generator.dart` | рисовал PNG (удалён) |
| `GenerationPipeline._placeholderOrNothing` (`generation_pipeline.dart`) | вызывал генератор при пустом запросе, бюджете, `null`/ошибке поиска, занятом URL, ненайденном `image_id` |
| `lib/api/prompts/system_prompt.dart` (`gen-ru-v8`, Правило 7) | требовал картинку каждой карточке → массовый поиск → массовые заглушки |
| `DriftGenerationCardStore._writeImage` | сохранял заглушку как обычное медиа |
| `lib/main.dart` `retryPlaceholders()` | поддерживал заглушки живыми при старте |
| `CardImageView` `errorBuilder → _ImageSkeleton` | маскировал ошибки декодирования |
| `CardContentView` (`mediaIds.first` без стороны) | ответная картинка видна до переворота (вторая первопричина) |

## 3. Как устранена первопричина

- Генератор **удалён**; pipeline не создаёт изображения ни при каком сбое
  (ADR-041). Неудачи — явные пометки `imageIdUnknown`/`imageNotFound`/
  `imageInvalid`; карточка остаётся без изображения.
- `PlaceholderMediaPurger` при старте удаляет старые заглушки (строки `media`,
  файлы, `.meta.json`, id из `media_json`), не трогая настоящие изображения;
  фоновый ретрай удалён.
- Проверка сигнатуры/MIME до записи (JPEG/PNG/WebP; пустые/битые байты
  отклоняются), `MediaIntegrityChecker` + `tool/media_integrity_report.dart`.
- Ошибки отображения — явные состояния: «изображение недоступно» (нет файла) и
  «не удалось показать изображение» (декодирование), с кнопкой повтора в
  редакторе, предпросмотре и всех сессиях.
- Промпт `gen-ru-v9` снимает требование картинки у каждой карточки: отсутствие
  изображения — норма.

## 4. Как ИИ выбирает изображения для обеих сторон

Схема ответа `gen-ru-v9` (ADR-042):

```json
"question_image_ids": ["img3"],
"answer_image_ids": ["img7"],
"image": {"query": "…", "fallback_query": "…", "kind": "diagram", "side": "answer"}
```

- `question_image_ids` — непосредственный стимул вопроса (схема/чертёж/график);
- `answer_image_ids` — то, что содержит или раскрывает ответ (формула, решение,
  таблица, подписанная схема);
- массивы обязательны, могут быть пустыми; несколько изображений разрешено;
- один id в обеих коллекциях запрещён (остаётся у вопроса, пометка
  `imageDuplicatedSide`); неизвестный id отбрасывается (`imageIdUnknown`);
- `image` — необязательный внешний поиск **настоящей** фотографии, сторона
  `question|answer|none`; поиск только для выбранной стороны и только если у
  неё нет файловых изображений; неудача — `imageNotFound`, без подмены;
- совместимость v5–v8: `image_id` → вопрос, `image_query` → поиск для вопроса,
  без `side` → вопрос; локальная терпимая схема принимает обе формы;
- промпт v9 требует перед выбором определить, что спрашивает карточка, что
  является ответом, какую роль играет изображение и раскрывает ли оно ответ;
  при неоднозначности — в сторону ответа; изображение должно быть связано с
  содержанием, а не с темой.
- `gen-ru-v8` сохранён дословно (`docs/prompts/gen-ru-v8.txt`), v9 — новая
  версия (`docs/prompts/gen-ru-v9.txt`, тест сверяет байты).

## 5. Как хранятся и отображаются questionMedia и answerMedia

- `cards.media_json` v2: `{"version":2,"question":[…],"answer":[…]}`;
  `schemaVersion` БД **не менялся**, миграции нет. Legacy-массив не знает
  стороны: occlusion/cloze — стимул вопроса, остальные — сторона ответа
  (безопасная политика: старый файл не раскрывает ответ до переворота).
- Домен: `Card.questionMediaIds`/`answerMediaIds`, `CardDraft` — независимые
  коллекции, загрузки и порядок (токены `upload:<index>`); `basic_reversed`
  меняет стороны у парной строки.
- Отображение: `CardContentView` — до переворота только `questionMediaIds`,
  после — только `answerMediaIds`; occlusion-холст общий (маски управляются
  раскрытием); несколько изображений на сторону; отсутствующий файл и ошибка
  декодирования — явные состояния с повтором.
- Редактор: два независимых списка — добавить, удалить, заменить, порядок,
  перенос на другую сторону; маски occlusion — у первого изображения вопроса.
- Предпросмотр: обе стороны отдельными подписанными секциями; живая карточка
  генерации показывает только изображение вопроса.
- Экспорт/импорт: `question_media_ids`/`answer_media_ids` в `cards.json`;
  старые архивы читаются по безопасной политике; id переназначаются с
  сохранением сторон; GC и чтение сессий используют объединение сторон.
