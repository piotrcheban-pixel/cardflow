## 1. Что сделано

1. **Фича-флаг `generationPipelineV3`** — `lib/domain/settings/app_settings.dart`,
   JSON-ключ `generation_pipeline_v3` (ADR-019 §1: неизвестные ключи и старый JSON
   без ключа → «выключено»). Переключатель — на экране «Провайдеры»
   (`settings-generation-pipeline-v3`), флаг читает `generationRunnerProvider`
   и передаёт в `GenerationPipeline(pipelineV3:)`. Пересборка не нужна.
2. **Вердикт завершения по журналу** — `lib/domain/generation/completion_verdict.dart`
   (`CompletionOutcome`, `fromLedger`, `auto`): `done` ⟺ `принято ≥ заказано`;
   отмена с принятым — `partial` (срез 7), сбой без карточек — `failed`; причина —
   машинный `ShortfallKind`. На пути v3 `generation_jobs.status` берётся из
   вердикта (ложный успех запрещён, ARCH §3.2).
3. **Метрики прогона** — `lib/domain/generation/generation_metrics.dart`:
   yield на 1000 входных токенов, acceptance rate, duplicate rate по уровням
   каскада, покрытие единиц, запросов на 10 карточек, p50/p95 батча (метод
   ближайшего ранга), JSON без текстов. Пишутся в `GenerationRunResult.metrics`
   и в debug-диагностику (`GenerationDiagnostics.runMetrics`).
4. **Дедупликация: пометка вместо удаления** — при включённом флаге почти-дубль
   (`front` ≥ 0.85 по триграммам) **остаётся** с пометкой
   `CardIssueCode.possibleDuplicate` (ARCH §3.4); точный дубль по-прежнему
   отбрасывается. На выключенном флаге поведение прежнее.
5. **«Почему?» по anchors** — `lib/api/generation/source_anchor.dart`:
   `SourceAnchorResolver` разрешает `quote_ref`/`source_excerpt` в **блок**
   `ContentModel` (`Block.text`, без склейки строк). Пайплайн на пути v3
   дописывает карточке `sourceAnchorText`/`sourceAnchorSection`; предпросмотр
   показывает блок в листе «Почему эта карточка?», без блока — кнопки нет.
6. **UI** — степпер этапов `analysis → planning → generation → validation` и
   «принято N из M» (`generation_v3_progress.dart`, только под флагом; старый
   прогресс не меняется); в предпросмотре — итог прогона и причины недобора,
   группировка карточек по первому тегу, пометки «Возможный дубль», «Обратная
   сторона», «Предупреждение: N». Все строки — в `app_ru.arb`, литералов нет.

## 4. Остаточные ограничения (известные, не маскируются)

1. **Этапы v3 не подключены к production-исполнению.** `ContentModel`/
   `UnderstandingService` (без HTTP-вызова `KnowledgeMapCaller`), `AllocationPlan`,
   `CardsBatchEngine`, `CardValidator`, `SemanticMatcher`, `ReplenishStage`,
   `DriftGenerationRunStore`/`importRunCards` существуют и покрыты тестами S1–S8, но
   конвейер по-прежнему исполняет прежний план и прежние запросы. Флаг среза 9
   переключает **слой завершения**: вердикт по журналу, пометку дублей, «Почему?»
   по блокам, метрики и UI. Полная проводка этапов — следующий шаг (см. Q19).
2. **Legacy не удалён.** Флаг по умолчанию **выключен** и TASK запрещает включать
   его без отчёта; удаление старого chunker/recovery-бюджетов/калибровки сделало бы
   нерабочим путь по умолчанию. Удалять — после перевода флага в default-on
   отдельным срезом, каждое удаление со ссылкой на тест (Q21).
3. **Маркер «Обратная сторона»** показывается для `basic_reversed` (двусторонняя
   карточка): значение `angle == reverse` из v3-партии придёт только с проводкой
   Generation-этапа (Q20).
4. **Метрики p50/p95** в отчёте — фейковые вызовы; живые прогоны (`CARDFLOW_LIVE_TESTS=1`)
   не запускались (нет разрешения/ключа в этом прогоне).
5. `GenerationMetrics.inputTokens` без факта `usage` падает на оценку входа плана
   (иначе yield был бы нулевым); источник числа в отчёте не различается.
