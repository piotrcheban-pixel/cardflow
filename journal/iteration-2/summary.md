- `CardDraft`: нормализация (`trim`, теги без `#`/дублей) и валидация по SPEC A8.4 — front ≤500/непустой, back ≤2000 (для cloze может быть пустым), теги ≤3, цитата ≤400; ошибки по полям (`CardDraftField → CardValidationError`).

- `ReviewRepository` (порт) + `ReviewUndo`; расширен `CardRepository` (CRUD/`cardById`); единый `CardState` (дубликат enum устранён).

**Данные (drift)**
- `DriftCardRepository`: create (uuid, `content_hash`, `basic_reversed` двумя строками с mutual `sibling_id` в транзакции), update (тип неизменен, hash пересчитан), delete (с очисткой `sibling_id` пары), валидация черновика на границе data-слоя.
- `DriftReviewRepository`: одна транзакция `UPDATE cards(state, fsrs_json, due, updated_at)` + `INSERT review_logs`; поля лога по A5 (`scheduled_days`, `actual_days`, `elapsed_ms`, `recognition_flag=0`); undo — компенсирующая транзакция (удалить лог + восстановить полный снимок карточки). Общий маппер строк `cards` (`card_row_mapper.dart`).
- Импорт `.zip`: `fsrs_json` валидируется и **перепривязывается к новому id карточки**, `state`/`due` из снимка; битый → `invalidCards`; `fsrs = null` → new/null (fix H1, `docs/archive-format.md`).

**UI (Material 3 Expressive, только ARB/ru)**

## Ретроспектива (шаг 7)

**Что замедлило:**
- Ревью шло параллельно с дописыванием Lead'ом T17/`_disposed`/ADR — reviewer фиксировал снимок и сверял дерево; выводы H1 пришлось перепроверять по двум зелёным тестам, но конфликтов не возникло. В следующей итерации reviewer запускается после коммита зелёной фазы, а Lead не меняет код до его завершения.
- Дубликат `CardState` (домен cards vs scheduling) всплыл только при попытке связать `Card` с планировщиком: пришлось сделать T1-рефакторинг до красной фазы, иначе красные тесты не компилировались.
- Заглушки красной фазы, возвращающие нейтральные значения, потребовали двух проходов (assertion-level вместо `UnimplementedError`); зато красная фаза стала доказательной.
- Форма карточки: `maxLength` у `TextField` молча обрезал 501 символ, из-за чего тест валидации «front >500» не ловил ошибку — найден при зелёном прогоне; исправлено (длины проверяет домен-валидатор).

**Какие тесты лишние/чего не хватило:**
- Лишних не появилось; `review_haptics_test` «каждая оценка имеет haptic» (isNotNull у non-nullable) — тавтологичен, оставлен как дешёвый guard.
- Не хватило **стыкового** теста «импорт ↔ планировщик»: H1 не ловился ни unit-тестами импорта (fsrs копируется как есть), ни unit-тестами маппера (чужой id → FormatException) — только их композицией. Интеграционный тест «оценка → export → import → сессия» теперь закрывает стык.
- Не хватало тестов на haptic-канал и цвета кнопок (добавлены в fix-итерации).

**Где команда/навыки помогли:** `flutter_test` + `drift` in-memory для data-тестов на боевой схеме; production-`ProviderContainer` для интеграционного flow; независимый reviewer нашёл H1 и M2/M3, которые не виделись изнутри зелёной фазы. Навыки из каталога по-прежнему недоступны (L5).

**Конкретное улучшение процесса (внесено в AGENTS.md):** независимое ревью запускается только на неизменяемом снимке (после коммита зелёной фазы); Lead не правит код до завершения ревью. Плюс: стыки слоёв (импорт/экспорт ↔ планировщик/сессия) подтверждаются интеграционным тестом на production-проводке, а не только unit-тестами каждого слоя.
