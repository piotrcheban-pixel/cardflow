## Решения (ADR-028)

### Шаг 1. Картинка — не только occlusion

- Секция изображения в форме доступна **всем** типам (`basic`, `basic_reversed`,
  `cloze`): выбрать/заменить/удалить картинку.
- Маски — отдельный переключатель «Маски (Occlusion)» для `basic`, по умолчанию
  **выключен**. Включён → редактор масок и прежняя валидация (изображение + ≥1 маска).
  Карточка с картинкой и выключенными масками — обычная иллюстрация под вопросом;
  `occlusion_json = null`.
- Домен: `mediaIds` документированно применим к любому типу; добавляются
  `CardDraft.primaryMediaId`/`Card.primaryMediaId`; валидация occlusion не меняется.
- UI-рендер (`CardContentView`) уже показывает иллюстрацию у карточки без
  `occlusion_json` — покрывается тестом.

### Шаг 2. Дневной лимит

- `ReviewQueue.build`: новые карточки, созданные **в текущий локальный календарный
  день**, не обрезаются лимитом новых (лимит остаётся для вчерашних/более ранних
  невыученных). Просроченные по-прежнему ограничены лимитом повторных. Порядок
  ADR-008 сохраняется.
- Дополнительно (для старых новых и исчерпанного лимита повторных): предупреждающий
  диалог «Дневной лимит исчерпан» с кнопками **«Продолжить без лимита»**,
  «Тренировка», «Отмена»; маршрут `/decks/:id/study?limits=ignore` (и `/feed`)
  отключает лимиты в сессии; пустое состояние сессии предлагает то же действие.

### Шаг 3. Поиск картинок ИИ

- `GenerationDiagnostics` в debug пишется в консоль (`debugPrint`), поэтому
  `flutter run` показывает сырой ответ модели (`image_query`) и итог поиска.
- Новый источник **Wikipedia pageimages** (`ru`, затем `en`): ищет статью, а не файл,
  поэтому понимает русские словоформы; порядок источников:
  Wikipedia → Wikimedia Commons → Openverse. DuckDuckGo/Pexels/Pixabay отклонены
  (bot-challenge / нужен ключ) — фиксируется в ADR и ограничениях.
- Если модель не дала `image_query`, для предметных `basic`/`cloze` запрос выводится
  локально из текста вопроса (`derivedImageQuery`), кроме случаев, когда пожелания
  пользователя запрещают картинки.
- Неудачный поиск не проглатывается: карточка получает `CardIssueCode.imageNotFound`,
  предпросмотр показывает предупреждение «Не удалось найти картинку по запросу»
  и счётчик; скачанная картинка видна в предпросмотре (тест).
- Бюджет суммарного поиска увеличен с 45 до 90 с; Openverse-таймаут 8 с сохранён,
  но он последний в цепочке.

## План тестов (red → green)

- Домен: `ReviewQueue` (сегодняшние новые вне лимита, сортировка, лимит 0),
  `derivedImageQuery`, `wishesForbidImages`, `CardDraft.primaryMediaId`,
  `Card.primaryMediaId`, `CardDraft` с медиа для basic/cloze/reversed.
- Данные/интеграция: `DriftCardRepository` — basic + imageUpload → media + файл;
  production-граф ежедневного лимита: сегодняшняя карточка доступна при исчерпанном
  лимите; маршрут `?limits=ignore`.
- UI: форма карточки (картинка без масок, cloze/reversed, переключатель масок,
  удаление картинки), экран колоды (диалог «Продолжить без лимита»), экран сессии
  (пустое состояние → продолжить), предпросмотр генерации (картинка и предупреждение).
- API: `WikipediaImageSearchService` (fake-Dio: разбор, скачивание, ошибки),
  composite-порядок, pipeline (derived query, `imageNotFound`, бюджет).
- Live: prompt-only DeepSeek (сырой ответ с `image_query`), Wikipedia/Commons,
  сквозная генерация → картинки.
- Windows: `flutter run -d windows`; `integration_test`-смоук с реальной drift-БД,
  MediaStore и UI: Basic + картинка без масок → отображается; лимит исчерпан, но
  сегодняшние карточки доступны; генерация с `image_query` → импорт → файл media.
