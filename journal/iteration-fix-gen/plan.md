## План шагов (цикл plan → test → implement → review → verify → remember → improve)

### Шаг 1 — диагностика (до любых исправлений)
- [ ] `diagnosis.md`: точная причина «Не удалось обработать фрагмент» (код `invalidResponse` без причины).
- [ ] Подтвердить/опровергнуть гипотезу LaTeX-escape фикстурами реальных «плохих» ответов.
- [ ] Проверить: валидатор отбрасывает весь фрагмент из-за одной карточки.
- [ ] Описать текущий подбор картинок (источник, запрос, выбор).
- [ ] Факты БД приложения `generation_jobs` (invalidResponse, truncated, files_json).

### Шаг 2 — промпт ген-ru-v5 и схема
- [ ] `lib/api/prompts/system_prompt.dart` — дословный raw-литерал `gen-ru-v5`; копия `docs/prompts/gen-ru-v5.txt`; тест байт-в-байт.
- [ ] `generation_prompt.dart`: блоки `<materials>`, `<wishes>`, `<limit>`, `<images>`; пустой блок `<materials></materials>`.
- [ ] Распределение общего числа карточек из пожеланий по фрагментам пропорционально объёму.
- [ ] Схема A8.4 + `image_id`: канон, проекции OpenAI/Gemini/Anthropic, локальный валидатор (image_id из `<images>`, image_query латиница ≤ 7 слов, tags ≤ 3).
- [ ] ADR-029: схема ответа модели (`image_id`, `image_query`); БД не меняется.

### Шаг 3 — генерация без файлов (Д1)
- [ ] Найти реальное место падения (БД: `error/invalidResponse` без файлов) → тест-воспроизведение.
- [ ] Имя колоды по умолчанию из темы, если файлов нет.
- [ ] Тесты: без файлов → карточки; пустой ввод → кнопка/сообщение; `source_excerpt` при пустых materials → null, карточка остаётся.

### Шаг 4 — изображения (Д2, Д3)
- [ ] Извлечение изображений DOCX/PPTX/ODT с контекстом (подпись, соседний абзац, слайд/страница), фильтр мусора.
- [ ] `<images>` только для изображений фрагмента: `id | файл | подпись | окружающий текст`.
- [ ] `image_id` → байты вложения → `GeneratedCard.image`; неизвестный id → null, без падения.
- [ ] Внешний поиск только при `image_id == null` и `image_query != null`; без запроса по тексту вопроса как запасного варианта.
- [ ] Предпросмотр: картинку можно убрать (и заменить) до импорта.

### Шаг 5 — LaTeX (Д4)
- [ ] Восстановление одиночных `\` перед латинскими буквами до `jsonDecode`.
- [ ] После разбора: `\f/\t/\b/\r/\n` внутри `$…$` + хвосты команд → исходная команда.
- [ ] Нормализация `\(…\)` → `$…$`, `\[…\]` → `$$…$$`; Unicode-индексы, markdown — очистка/пометка.
- [ ] Widget-тесты `LatexText`/`CardContentView` на фикстурах шага 1.

### Шаг 6 — импорт при частичном успехе (Д6)
- [ ] Коды причин фрагмента: truncated, refusal, safety, json_parse, schema_invalid, validator_rejected, network, http_4xx/5xx — в `generation_jobs` и отладочный лог.
- [ ] Невалидная карточка не отбрасывает фрагмент.
- [ ] Предпросмотр: «Импортировать все»/«Импортировать выбранные» активны при частичном успехе; кнопка неактивна только без выбранных карточек; ошибки списком + «Повторить неудавшиеся».
- [ ] Тест: 2 успешных фрагмента + 1 упавший → импорт создаёт колоду; повтор только упавшего.

### Шаг 7 — оценка качества (Д5)
- [ ] Мягкие проверки: ответ/формула из back во front; front без «?» и не cloze; back > 200 символов/3 предложений; back — только расшифровка обозначений; image_query для аксиом/законов/теорем/формул.
- [ ] Eval-набор: 3 сценария (тема без файлов; DOCX с формулами/рисунками; PPTX), фикстуры ответов → тесты валидатора.
- [ ] Live-тест (ключ present/absent): тема «Статика: аксиомы, связи, плоские фермы», 20 карточек, доля пометок.

### Шаг 8 — проверка и завершение

- [ ] `fvm flutter build windows --release --no-pub`; ручные сценарии (а/б/в) или KNOWN_LIMITATIONS.
