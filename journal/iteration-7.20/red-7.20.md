Последнее падение — точное воспроизведение жалобы владельца: заказ 40, план
может выдать 26 (мягкая ёмкость фикстуры), и это объясняется не материалом, а
«планом/бюджетом». После исправления сообщение обязано говорить о ёмкости
материала и не подменять заказ.

## Что должно стать зелёным

1. `CardAllocation.achievable == requestedCards` при любом заказе, если есть
   содержательные разделы; `estimatedCapacity`/`materialLimited` — отдельно.
2. Партии: `⌈заказ / вместимость⌉`, заполнение до вместимости, остаток последней.
3. `PlanWarningCode.materialCapacityBelowRequested` вместо `requestedAbovePlan`
   для нехватки материала; `requestedAbovePlan` — только «нет разделов».
4. Технический предохранитель числа партий (`maxChunks`) — `tooManyChunks`
   вместо зависания на `int.max`.
5. UI: «Запрошено: N карточек», «Подробнее» с числом карточек, максимумом
   партии и распределением; фактически созданное количество при исчерпании.
