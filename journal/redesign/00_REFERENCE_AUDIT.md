## Отличия Gemini-прототипа от CardFlow (что нельзя переносить)

| В прототипе | В CardFlow | Решение |
|---|---|---|
| «Синхронизировано», «Александр В.», PRO-статус | Нет синхронизации и учётной записи | Не переносить; в панели — реальный остаток повторений |
| Категории/эмодзи/«Изучено 90%+» у колод | У колоды только имя, настройки, даты; счётчики карточек | Реальные счётчики `DeckSummary`; монограмма из имени |
| «Серия 14 дней», «Рекорд 28» | В статистике нет серии/рекорда как поля | Серия вычисляется из годовой карты (реальные дни), рекорд не показываем |
| Кривая забывания FSRS, распределение оценок | `StatisticsSnapshot` не содержит этих рядов | Не рисовать; вместо них — реальные блоки (удержание 30 дней, карта года, неделя, слабые темы, прогноз) |
| Нижняя навигация отсутствует, меню-бургер | Была `NavigationBar`/`NavigationRail` | Панель + `Drawer` (ADR-038), все маршруты сохранены |
| «Импорт .apkg / JSON» | Импорт — ZIP-архив CardFlow (ADR-006) | Подпись «Импорт», реальный ZIP-импорт |
| Карточка с «Верифицировано» и озвучкой | Нет проверки фактов и TTS | Не показывать фиктивные признаки |
| API-провайдеры по названиям («Claude 3.5») | Аккаунты провайдеров (ADR-020) | Реальный список аккаунтов/моделей |

## Спорные решения

1. **Тёмные `on-primary`.** В CSS v2 `--cf-on-primary: #FFFFFF` при
   `primary: #818CF8` (контраст ≈2.6:1). Для заливки основных действий в
   тёмной теме используется `primary-container` (#6366F1) с белой подписью
   (≈4.0:1) — как на тёмном снимке v1; токен `onPrimary` остаётся тёмным для
   Material-компонентов, читающих его напрямую.
2. **Панель «Сессия»** в макете скрыта; в CardFlow её и не было (мёртвый пункт
   запрещён). 
3. **Поиск в панели** открывает поиск экрана «Колоды», а не глобальную
   командную палитру (её в приложении нет — не создаём фиктивную).
4. **Мобильная навигация** заменена на `Drawer` (ADR-038) — это изменение
   принятого решения, а не «косметика».

## Ограничения аудита

- `redesign/2` не содержит мобильного снимка; мобильная композиция выведена из
  классов (`lg:` = 1024) и снимка `r1-mobile.png`.
- Снимки сделаны в 1440×900; промежуточные ширины (1024, 768) проверяются
  widget-тестами и ручным запуском.
