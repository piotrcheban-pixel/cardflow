## 4. Порог N* и правило

Правило: материал с числом единиц ≥ N* → v3, меньше → legacy. Выигрыш v3 — одновременно: `cleanRate` не ниже, `dupRate` не выше и `absoluteClean` не ниже legacy.

Выигрышные объёмы: []; причина `noCrossover`.

**N* данные не дают:** v3 не выигрывает ни на одном измеренном объёме (10, 33 единиц). Правило принимает вид «v3 для объёма ≥ N, legacy иначе» с пометкой **«на границе выбор не определён данными»**; фактически это legacy для всех измеренных объёмов.

Сравнение чистых по ячейкам (§2): v3 не ниже legacy на 0 из 4 сопоставимых пар — объём сравним, а качество по объёму всё равно не окупает меньший выход карточек. Единственная величина, где v3 близок к legacy, — cleanRate на статье (`+0.0 п.п.`); на учебном тексте v3 хуже по `dupRate` на всех заказах.

Слепая выборка — `blind-sample-17.md` / `blind-key-17.json` с тем же статусом: измеряется следующим замером, где стенд пишет `cards`.

## 6. Вердикт по выпуску

Правило п. 10 **не включается по умолчанию**: данные не дают N*, авто остаётся legacy (`kGenerationPathV3MinUnits = null`), v3 — ручное переопределение режима. Доля годных из слепой выборки не измерена (нет сохранённых карточек), поэтому TASK п. 12 не может показать «доля годных v3 не ниже legacy» — консервативный вывод тот же: v3 не включается автоматически. Разница, которую видно числами, — доля дублей v3 (до 51 % на учебном тексте) уходит задачей на промпт S18.
