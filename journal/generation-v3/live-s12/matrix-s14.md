# Срез 14 — сопоставимая база и вердикт по флагу

Источник — существующие `live-s12/matrix.jsonl` (новых платных прогонов не делалось). Две величины рядом: **absoluteClean** — число чистых карточек (доля без объёма вводит в заблуждение: 100 % из 15 и 97 % из 189 — разное) и **cleanRate_matched** — чистые / произведённые на сопоставимой базе.

Сопоставимая база: единицы, где **оба** пути произвели хотя бы одну карточку. В `matrix.jsonl` нет пер-юнитных карточек, но есть `coverage`; у обоих путей во всех решающих ячейках `coverage = 100 %` — единиц без карточки нет, значит из базы не выпадает ни одна произведённая карточка (`matched = произведено`). При неполном покрытии база из агрегатов **невосстановима** — там было бы `—`, а не догадка. «Топ-80 по salience» для ячеек 150/300 требует пер-карточных значимостей, которых матрица не сохранила; это ограничение L230, а не подмена.

## Разбор 188/300 после среза 14

В старых записях статьи заказ 300 дал 188 принятых при `stage = ready`: план повторял слоты `unit_id + angle` сверх четырёх на единицу. Срез 14 запрещает такие слоты конструктором плана: `planned = capacity = 188`, `requested` остаётся 300, план помечен `materialLimited`; итог прогона — `partial` с причиной `exhausted_material` и числом 188, добор не делает ни одного запроса (свободных слотов нет). Числа таблицы выше — из прогонов S12 (новых платных не было), поэтому строка «ready» в них ещё старая; при следующем живом прогоне ячейка придёт как `partial`.
