# Итерация 7.5 — улучшение (ретроспектива)

**Что замедлило:**
- Breaking-рефакторинг контрактов (`ApiKeyStore`, `GenerationRequest`, `GenerationRunRequest`)
  задел 16 тестовых файлов; первая попытка прогнать всё целиком дала длинный список
  compile-errors, который пришлось разбирать повторно. Ускорило бы «сначала `test/helpers/`,
  потом `flutter analyze test` перед полным прогоном».
- Проверка распознавания «хардкод-текста» guard-ом поймала интерполяцию внутри `Text(...)` —
  в проекте строку для UI нужно собирать в локальной переменной, а не в литерале с `$`.
- Тестовые ключи вида `sk-…` длиннее 20 символов падают в `no_secrets`; безопаснее короткие
  маркеры без префикса `sk-`, либо тестовая константа не должна совпадать с паттерном.

**Что сработало:**
- Сначала домен + тесты (каталог/аккаунты), затем данные, затем API, затем UI — порядок зависимостей
  не отлаживался в виджетах.
- Живой прогон DeepSeek и Windows integration-тест сразу ответили на вопрос «а хранилище точно
  работает?» — без этого диагноз остался бы догадкой.
- Диалоги в тестах: `pump()` + `pump(300 ms)` и `find.descendant(of: AlertDialog, ...)` — стабильно.

**Одно улучшение процесса (внесено в AGENTS.md, «Ретроспектива итерации 7.5»):**
- сохраняемые сущности с несколькими полями валидировать/писать **независимо** (урок D1);
- результат read-back хранилища обязан влиять на сообщение об успехе (D3);
- платформенные плагины проверять `integration_test`-ом на десктопе (`-d windows`), а не только моками;
- при breaking-рефакторинге сначала обновлять общие фейки `test/helpers/`.
