## Low — исправлено попутно

- Оценка токенов в UI включает системный промпт и обёртку (выход — фактический из ответа).
- DnD-файлы получают размер через `XFile.length()`.
- `_pickFiles` проверяет `mounted` после системного пикера.
- `splitInHalf` делит по runes, не разрезая суррогатные пары; тест с эмодзи.
- `generation_jobs.cards_count` — «получено моделью»; импорт обновляет только `result_deck_id`.
- Сообщение валидации предпросмотра больше не говорит только о пустом вопросе.
- Пункт «Сгенерировать карточки» добавлен иконкой в Toolbar экрана колоды (A6.3), меню сохранено.
- Гонка retry ↔ import закрыта взаимными guard-проверками.
- Плюрализация «Примерно N токенов».

## Осознанно не исправлено (в известные ограничения)

- Точная оценка выхода модели до отправки: UI показывает оценку входа (промпт + материалы + обёртка),
  фактический расход — после ответа. Точный расчёт требует токенизатора модели, это вне MVP.
- Предупреждение о большом объёме сформулировано нейтрально; число фрагментов зависит от модели.
- Реальный DnD/picker на устройствах, мобильные `content://` — известные ограничения L11/L23.

## Изменение красных ожиданий (ревью low)

В зелёной фазе поправлены два **неверных** ожидания красной фазы, а не ослаблены проверки:
- `truncated` при одном исходном фрагменте: 1 исходный вызов + 2 половины = **3** вызова (в красной
  фазе ошибочно ожидалось 2);
- порядок чанков: проверка `first/last` заменена на `indexWhere('Первый') < indexWhere('Второй')`,
  потому что последний жёстко нарезанный кусок не обязан начинаться со слова «Второй».
Оба факта зафиксированы здесь и в `journal/iteration-3c/red-generation.md`; поведение SPEC не менялось.
