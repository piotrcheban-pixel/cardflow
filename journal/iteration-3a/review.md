## High

### H1. RTF: `\*`-группы не пропускаются, вместо них пропускается следующая группа → потеря видимого текста
**Файл:** `lib/api/parsers/rtf_parser.dart:137-140` (`\*` → `_skipNextGroup = true`), `:84-92` (флаг применяется к следующему `{`), `:74`.
**Суть:** при `\*` конвертер не начинает пропуск *текущей* группы (она уже открыта `{` до `\*`), а вооружает флаг, который срабатывает на *следующем* `{` — и пропускает следующую, обычную группу. Как следствие: содержимое `{\*\...}` выводится как текст, а первая нормальная группа после него теряется.
**Воспроизведено** временными пробами (в репозитории не оставлялись):
- `{\rtf1\ansi {\*\generator Word;}{\field{\*\fldinst HYPERLINK "http://x"}{\fldrslt Link text}} tail}` → `"tail"` — **потерян весь видимый текст поля/гиперссылки**;
- `{\rtf1\ansi {\*\unknown secret} visible}` → `"secret visible"` — текст starred-группы утёк;
- `{\rtf1\ansi {\*\unknown x}{Real Group} after}` → `"x after"` — пропущена следующая обычная группа.
**Почему важно:** Word/LibreOffice RTF насыщен `{\*\...}`-группами (`generator`, `bkmkstart`/`bkmkend`, `latentstyles`, `themedata`, поля/гиперссылки); получаем молчаливую потерю законного текста и мусор в извлечении. Нарушает ADR-010 §7 («управления `\*` — пропуск группы») и цель A8.3; карточки будут генерироваться из искажённого текста без ошибки пользователю.
**Минимальный фикс:** при `\*` сразу ставить `_skipping = true` для текущей группы (состояние группы уже на `_skipStack`; на `}` восстановится), убрать `_skipNextGroup`; добавить тесты: `{\*\unknown …}` (пропуск), starred-группа перед обычной группой (обычная сохраняется), RTF с полем/гиперссылкой (видимый текст сохраняется).

### H2. XLSX обходит ZIP-лимиты ADR-010 (zip-bomb/OOM для `.xlsx`)
**Файл:** `lib/api/parsers/xlsx_parser.dart:27-35` (`Excel.decodeBytes(bytes)`), ADR-010 §4 («Внутри ZIP-форматов: лимит записей 10 000, лимит размера записи 32 МБ, суммарный распакованный объём 120 МБ — защита от zip-bomb»), §5 (XLSX — ZIP-контейнер).
**Суть:** DOCX/PPTX/ODT проходят через `SecureZip` с лимитами, а XLSX отдаётся `excel_plus`, который использует ленивый `ZipDecoder` **без** проверки числа записей/размеров и затем разворачивает части (`worksheet`, `sharedStrings`, `styles`) в память в изоляте. Входной файл ограничен 25 МБ, но это не ограничивает распакованный объём: заявленный `uncompressedSize` может быть гигабайтным, а deflate с 25 МБ даёт до ~25 ГБ. OOM изолята — это падение всего процесса, а не аккуратный `ParsedFileFailure`.
**Почему важно:** обещанная ADR-010 защита не выполнена ровно для одного из четырёх ZIP-форматов; пользовательский `.xlsx` может уронить приложение вместо «Не удалось прочитать файл».
**Минимальный фикс:** до `Excel.decodeBytes` валидировать те же байты `SecureZip(bytes)` (конструктор ленив — читает только central directory) или вынести общий `validateZipLimits(bytes)` и применить ко всем 4 ZIP-форматам; тест на архивы: >10 000 записей, запись >32 МБ, сумма >120 МБ → `ParserException(unreadableFile)`.

## Medium

### M1. RTF: сырые CR/LF в RTF-потоке выводятся как текст → лишние переводы строк
**Файл:** `lib/api/parsers/rtf_parser.dart:104-107` (любой символ вне `{}`/`\` пишется в output; `\`+newline обрабатывается только в `:159-161`).
**Проба:** `{\rtf1\ansi Hello\r\nWorld\par End}` → `"Hello\nWorld\nEnd"`. По спеке RTF CR/LF, не предварённые `\`, игнорируются; многие конвертеры переносят строки RTF-потока (историческое ограничение 255 символов) — получим мусорные переводы строк, искажающие абзацы и границы разделов A8.5.
**Минимальный фикс:** в основном цикле игнорировать `\r`/`\n`; добавить тест на RTF с переносами.

### M2. RTF: `\ucN` не ограничен группой; `\ansicpg` KOI8-R не реализован (ADR-010 §7)
**Файл:** `lib/api/parsers/rtf_parser.dart:199-200` (`_unicodeSkip` — одно глобальное поле), `:84-99` (в `_skipStack` нет состояния `\uc`), `:228-236` (`_flushEscapedBytes`: только cp1251/cp1252/UTF-8, KOI8-R и прочие `\ansicpg` → default cp1251).
**Пробы:** `{\rtf1\ansi {\uc0\u1040\u1041} \u1042?}` → `"АБ В?"` (по спеке `\uc` восстанавливается на выходе из группы → ожидалось `"АБ В"`); `\ansicpg20866` + `\'hh` → `"рТЙЧЕФ"` (ожидалось «Привет»).
**Почему важно:** ADR-010 §7 обещает «cp1251/cp1252/KOI8-R через enough_convert» и `\ucN`; на деле KOI8-R RTF декодируется мусором, а `\uc0` в группе ломает пропуск fallback-символов дальше по документу.
**Минимальный фикс:** включить `_unicodeSkip` в стек групп (push/pop вместе с `_skipping`); добавить ветку `Koi8rCodec` для cp 20866/21866 **или решение владельца** — убрать KOI8-R из ADR-010 и записать ограничение в `KNOWN_LIMITATIONS`; тесты на `\uc0` внутри группы и на cp1252/koi8.

### M3. DOCX: таб-стопы `w:pPr/w:tabs/w:tab` попадают в текст абзаца как `\t`
**Файл:** `lib/api/parsers/docx_parser.dart:104-113` (`_paragraphText` обходит **все** `descendantElements` абзаца, включая `w:pPr`).
**Проба:** абзац `Первый` + абзац `<w:pPr><w:tabs><w:tab w:val="left" w:pos="720"/></w:tabs></w:pPr><w:r><w:t>Второй с табстопом</w:t></w:r>` → `"Первый\n\tВторой с табстопом"` (мусорный `\t` в начале строки).
**Почему важно:** таб-стопы — обычная разметка Word (оглавления, списки, выровненные блоки); табы попадают в нормализованный текст и в карточки.
**Минимальный фикс:** собирать текст только из прогонов (`w:r`) или пропускать поддерево `w:pPr`; тест на абзац с `w:tabs`.

### M4. DOCX: текст в блочных `w:sdt` (content controls) и `w:customXml` теряется
**Файл:** `lib/api/parsers/docx_parser.dart:54-70` — `switch` только по прямым детям `w:body` (`p`/`tbl`); `w:sdt`/`w:customXml` игнорируются.
**Проба:** абзацы внутри `w:sdt/w:sdtContent` и `w:customXml` не попали в текст (`"Первый\nПоследний"` вместо трёх строк).
**Почему важно:** content controls — типовые конструкции шаблонов/форм Word; молчаливая потеря текста в поддерживаемом формате.
**Минимальный фикс:** рекурсивный обход блоков (`p`, `tbl`, `w:sdt→w:sdtContent`, `w:customXml`), фильтруя абзацы таблиц; тест.

### M5. ODT: обход всех `text:p`/`text:h` включает оглавление и примечания → дубли/чужой текст
**Файл:** `lib/api/parsers/odt_parser.dart:40-50` (`content.descendantElements` без skip-list).
**Проба:** ODT с `text:table-of-content/text:index-body` (копия заголовка), заголовком, текстом и `office:annotation` → `"Оглавление: Раздел 1 ...... 1\n\nРаздел 1\nТекст\nПримечание рецензента"`.
**Почему важно:** LibreOffice штатно хранит оглавление в `content.xml`; дублирование материала перед чанкингом/генерацией (A8.5 шаг 9 отсеивает не всё), плюс комментарии рецензентов попадают в текст.
**Минимальный фикс:** skip-list сервисных элементов (`text:index-body`/`text:table-of-content`, `office:annotation`, `text:tracked-changes`) или обход только содержательных потомков `office:text`; тест с TOC.

### M6. ZIP: `ZipDecoder` в lenient-режиме — структурные ошибки подавляются, `catch` в `SecureZip` почти недостижим
**Файл:** `lib/api/parsers/zip_xml.dart:43` (`arc.ZipDecoder().decodeBytes(bytes)` без `verify`/`throwOnError`), `:44-49` (catch).
**Проба:** `ZipDecoder().decodeBytes([0x50,0x4B,3,4,0,1,2])` и `[1,2,3,4]` → `Archive(files=0)` **без исключения** (archive 4.6 `guardDecode` подавляет data-ошибки, если `throwOnError=false`). Значит частично/полностью повреждённый ZIP может дать пустой/неполный архив, и пользователь увидит `emptyText`/«нет текста» или потеряет часть документа вместо `unreadableFile`; ветка catch фактически не исполняется (по lcov строки 45/47 не покрыты).
**Минимальный фикс:** `ZipDecoder().decodeBytes(bytes, verify: true, throwOnError: true)` (и `readBytes`/`readXml` уже маппят в `ParserException`); тест на битый central directory и на битую запись.

### M7. XLSX: формула без кэша `<v>` пропадает; `DateTimeCellValue` не нормализуется к дате (ADR-010 §5)
**Файл:** `lib/api/parsers/xlsx_parser.dart:72-80`.
**Проба:** `A2` = дата+время (`2024-06-16T12:00:00.000Z`), `B2` = `<f>A1</f>` без `<v>` → строка вывелась как `"2024-06-16T12:00:00.000Z"`; `B2` исчезла полностью (пустая ячейка + обрезка хвостовых), хотя в файле есть формула.
**Почему важно:** (а) файлы, сохранённые не-Excel инструментами, часто не пишут кэш формул — содержимое теряется без ошибки; (б) ADR-010 §5 обещает даты → `yyyy-MM-dd`, а ячейки с временем дают UTC-таймстамп (`DateTimeCellValue.toString()`); числовые даты с date-форматом при этом корректно дают `yyyy-MM-dd` (проверено пробой) — проблема только у типа с временем/без кэша.
**Минимальный фикс (нужно решение):** для `cachedValue == null` — fallback (текст формулы с пометкой или явный пропуск + документирование); обработать `DateTimeCellValue`/`TimeCellValue` по ADR; тесты на формулу без кэша и дату-со-временем.

### M8. Тестовые пробелы по критериям C8/C10/C12 (заявленные критерии не покрыты)

- **C8/PDF:** покрытие `pdf_parser.dart` **78.1%** (25/32); не проверены `PdfPasswordException` (запароленный PDF → `unreadableFile`), `PdfException` (битый), ошибка `pdfrxInitialize`, multi-page (все тесты на 1 страницу), страницы с пустым текстом среди непустых.
- **C12/изолят:** unit-тест инжектирует runner, исполняющий задачу «на месте»; интеграционный тест ловит только ошибки, брошенные **до** изолята (несоответствие сигнатуры, `.doc`). Я проверил вручную: `Isolate.run(() => throw ParserException(scannedPdf))` → на выходе `ParserException` с тем же кодом (тип sendable), т.е. механизм работает, но регрессию ничто не ловит.
**Минимальный фикс:** `zip_xml_test.dart` (лимиты/ошибки/BOM-ветки), PDF-тест запароленного (минимальный encrypted PDF-фикстур или платформенный skip + известное ограничение), интеграционный тест на скан-PDF/пустой документ через реальный `Isolate.run` с ожиданием конкретного кода.
